# Ren'Py 游戏汉化

在原版隔离副本中完成 Ren'Py 提取和部署，以 ATT Generic 管理翻译状态、模型调用、术语与质量门禁。
当前 ATT 没有原生 Ren'Py 命令域；本技能组织外部转换流程，不提供通用解包器或 Ren'Py 解析程序。

## 读取顺序与边界

先读取 [ATT 翻译主线](../translate-with-att/SKILL.md)，沿用其术语、Translate、QA、Manual 与恢复步骤。
本技能只补充 Ren'Py 与 Generic 的交接；共享命令和状态不另立规则。

- 使用完整 ATT 发行及其包内文档。项目、配置、资源与输出路径遵守
  [发行物规格](../../docs/runtime/distribution.md)，不依赖未公开的路径开关。
- Generic 转换前读取 [JSONL](../../docs/generic/jsonl.md)；执行时按阶段读取
  [Init](../../docs/generic/init.md)、[Extract](../../docs/generic/extraction.md)、
  [Translate](../../docs/generic/translation.md)或 [WriteBack](../../docs/generic/write-back.md)。
- 原版是只读基线。解包、模板生成、编译、字体修改和测试都在隔离副本或项目工作目录进行；续跑保留
  已有发行副本和 ATT 进度，不用原版静默覆盖。
- 翻译和审校权限以任务发起者的明确范围为准；技术调查不自动扩大内容处理权限。只要求维护经验时，
  不因此启动翻译、窗口测试或封包。

## 1. 确认引擎与提取范围

记录游戏所带 Ren'Py 版本、入口、实际游戏目录及 `.rpy`、`.rpyc`、`.rpa` 的分布。使用该游戏的引擎，
或已验证兼容的 SDK；不能把系统 Python、新版 SDK 或其他游戏的编译产物当作同一运行环境。

有原生模板时，核对模板对应的脚本范围；需要生成或更新模板时，在副本中使用匹配引擎。只有归档或
编译脚本时，先确定可用且兼容的提取方式，记录失败来源；少量 loose `.rpy` 不证明已覆盖整个游戏。
若当前工具不能完整读取必要来源，保留缺口并报告，不以现有模板数量声称完成。

建立正文、菜单、角色名、自定义界面、启动提示和图片文字的来源清单。详细提取与界面接入方法见
[提取与显示消费者](references/extraction-and-consumers.md)，在生成 Generic 输入或定位漏翻时读取。

## 2. 建立 Generic 往返映射

外部转换负责 Ren'Py 语法和定位，ATT 只接收符合现行 JSONL 契约的文本。

- 按场景和真实语境划分文件与 Group，保留自然顺序；一个翻译模板文件不必整体成为一个 Group。
- 单独保存源文件、原生翻译块/字符串身份、结构位置、原值与源文件指纹的映射。定位信息不作为
  JSONL 私有字段，也不发送整段源码、动作代码或配置文件给模型。
- ID 稳定且写回位置唯一。先核对完整来源到 JSONL 的覆盖，再用小范围不改正文的往返验证语法、
  引号/转义、多行值与非目标结构保持不变。新适配器不能只验证计数。

没有可靠反向映射时，先补齐转换能力；Generic WriteBack 不会直接生成可运行的 Ren'Py 游戏。

## 3. ATT 翻译与续跑

按主技能执行 Init、Extract、完整 Manual 导出、术语、Placeholder、Translate 与 QA。
Ren'Py 插值、文本标签和自定义标签的保护依据当前 [Placeholder 规格](../../docs/translation/placeholders.md)
及实际游戏结构确认，不能直接套用 RPG Maker 控制码规则。

完成判断分别覆盖 ATT 当前命令状态、实际待办与拒绝、外部来源覆盖和 QA 结论。映射位置总数、
去重后请求数、当前译文及保留原文不是同一计数；规则跳过的格式项也不能直接认作漏翻。

少量新来源沿原项目补 Extract；保持原 Group 的语境和稳定 ID，核对受影响范围。拒绝与质量修订按
主技能的重试或 Manual 流程处理，不为少量失败清空数据库或重跑全部已接受内容。

## 4. 反向转换与显示接入

消费本轮成功 WriteBack 的全部 JSONL，按映射生成对话翻译块与字符串表，再部署到已有游戏副本。
校验每个映射位置的值、原生身份及唯一消费者；源文件漂移、缺失、重复或匹配非唯一时停止该位置的写入。

新增字符串表还需确认显示调用采用它。`show text`、`Text(...)` 和 Python 生成界面可能不在原生模板中；
引擎缺失计数为 0 不能证明这些调用已覆盖。保持变量插值、文本标签、动作和资源查找键的技术含义。

使用匹配引擎编译，核对日志和有效产物。含仅编译脚本的项目在编译前确认保留机制，避免删除必需的
孤立 `.rpyc`。同名 screen 和归档/loose 脚本并存时，核对实际加载来源，不只查看文件名和时间戳。

## 5. 字体、补丁与验收

出现缺字、替换字体或交付独立补丁时，读取 [字体与补丁验证](references/fonts-and-patches.md)。
核对有效语言、默认及直接样式字体、替换映射与特殊符号覆盖；独立补丁从已验证部署清单生成，
检查实际 ZIP，并在干净原版副本验证安装结果。

交付说明正文与界面覆盖、保留原文及未决项、字体、WriteBack 部署、静态检查与人工实机检查各自结果。
编译、字体加载或翻译计数通过不等于实际游玩通过；实机清单覆盖启动提示、标题、菜单、对话、
自定义界面、换行裁切和存读档。窗口测试由任务发起者指定的人工完成。

反馈返修从实际显示位置反查唯一来源，再从最早受影响阶段继续。启动异常先核对日志与当前副本；
确需原版对照时使用原版测试副本，不能在只读原件中生成缓存和存档。原版同样失败只是本次环境的
对照结果，不构成字体或译文的根因证明。
