# Ren'Py 字体与独立补丁验证

用于中文缺字、字体接入及独立补丁交付。沿用本轮已核对脚本来源和译文写入结果的游戏副本；
只有交付要求包含独立补丁时，才执行补丁生成和安装、回退验证。

## 实际加载的字体与缺字

先区分原文未进入翻译查找与译文已经部署但缺字。字体问题核对实际语言下的样式及加载关系：
默认字体、`gui.*_font`、直接样式 `font`、文本字体标签、字体替换映射和既有 `FontGroup`。
语言样式机制见 [Ren'Py 样式翻译](https://www.renpy.org/doc/html/translation.html#style-translations)。

- 从字体别名继续追踪替换映射，确认最终加载的字体文件。
- 按最终部署文本所需字符检查 glyph，并保留游戏使用的字体名称与加载关系。字体许可随交付保存。
- 主字体缺少特殊符号时，可以把这些码点保留到支持它们的字体，其余文本使用目标语字体。
  [FontGroup](https://www.renpy.org/doc/html/text.html#font-groups)采用第一个覆盖该字符的范围；
  按这个顺序确认每个所需字符实际使用的字体及 glyph。
- 保留游戏已有的独立 emoji 字体及特殊字符映射；需要替换时，逐项确认替代字体支持这些字符。

核对当前启用语言与游戏已有语言选择机制，保留用户的持久化设置；不能用每次启动清空 persistent
或强制改写偏好来证明中文已启用。字体加载和 glyph 覆盖通过仍需人工观察换行、裁切及符号形状。

## 从最终部署清单生成补丁

1. 记录适用游戏版本与原件基线，确认游戏副本已采用本轮 WriteBack，相关显示调用能查到译文。依据部署
   清单选择补丁文件；源脚本在 `.rpa` 内时，新增加的 loose 脚本仍可能是必需覆盖项，不能只看
   物理目录内“修改了哪些既有文件”。
2. 收纳所需译文、消费者脚本、语言/字体接入及字体。若包含 `.rpyc`，由匹配引擎从最终 `.rpy`
   编译并核对配对；不把其他版本的旧编译文件或诊断钩子带入补丁。
3. 提供安装位置、适用版本、补丁文件清单、哈希、字体许可和卸载说明。ZIP 根目录与安装方法一致，
   例如 `game/` 合并到 EXE 所在目录。另列安装和首次编译会新增或覆盖的文件，供卸载与回退使用。
4. 排除无关本体资源、游戏 EXE、ATT 程序、配置、凭据、数据库、日志、缓存、存档及工作脚本。
   显示译文必需的完整脚本属于补丁文件，不能因其中含未改动代码而遗漏。
5. 校验实际 ZIP 的文件集合、重复/不安全路径、CRC 与逐条内容哈希，确认与待打包目录一致。
   再按下文验证安装及卸载恢复。

回退范围包括引擎生成或改写的 `.rpyc`，即使 ZIP 只提供 `.rpy`。例如只安装 `patch.rpy`，
首次编译后也会生成 `patch.rpyc`；删除源脚本后，孤立编译脚本仍会执行，见
[Ren'Py 脚本加载规则](https://www.renpy.org/doc/html/language_basics.html#files)。安装前按目标目录
的实际状态区分新增与覆盖，在首次覆盖或编译前备份会被改写的原件，包括原有同名 `.rpyc`。
卸载时删除本补丁新增的源脚本和编译脚本，恢复被覆盖的原件；字体和其他补丁文件也按此处理。
清理限定在已经确认属于本补丁的文件，不删除整个 `game`、`tl`、其他孤立 `.rpyc` 或用户存档。

## 干净安装、回退与验收边界

从只读原件复制测试基线到工作目录，先核对版本及关键资源，再从**交付的实际 ZIP**安装，
而不是直接复制待打包目录。使用匹配引擎验证编译、翻译缺口、当前启用语言、字体及相关显示调用。
需要执行 CLI 时，先核对初始化代码的副作用和该版本的存档重定向方式，保持测试与用户游戏状态隔离。

解压后先按补丁文件清单校验内容；编译后核对源脚本、字体、实际加载的脚本定义和字符串查找结果。
引擎可能重新生成 `.rpyc`，不能把合法重编译后的哈希变化直接判为 ZIP 损坏。

在同一测试副本完成一次编译后，按交付的卸载说明执行回退：确认新增的 `.rpyc` 已清理、被覆盖的
原件已恢复，并重新核对原版脚本的加载来源。卸载后的检查保留原有编译脚本，避免通过全局清理孤立
`.rpyc` 掩盖回退遗漏。用户存档保持不变。

分别记录静态产物、编译/初始化、卸载/回退和人工实机的结果：

- 静态产物：来源映射和部署清单一致，原件及非目标资源未变。
- 编译/初始化：脚本编译成功，显示调用查到预期译文，字体能加载所需字符；缺失计数只覆盖引擎登记项。
- 卸载/回退：补丁新增文件及其编译脚本已清理，被覆盖原件已恢复，原版脚本重新被加载。
- 人工实机：启动、菜单、对话、自定义界面、布局和存读档；未执行就明确未验证。
