# Ren'Py 字体与独立补丁验证

用于中文缺字、字体接入及独立补丁交付。沿用本次已验证的游戏副本；路径与执行权限服从当前任务，
不把维护者机器上的安装位置或某款游戏的符号清单写成默认。

## 有效字体和缺字

先区分原文未进入翻译查找与译文已经部署但缺字。字体问题核对实际语言下的样式及加载关系：
默认字体、`gui.*_font`、直接样式 `font`、文本字体标签、字体替换映射和既有 `FontGroup`。
语言样式机制见 [Ren'Py 样式翻译](https://www.renpy.org/doc/html/translation.html#style-translations)。

- 配置仍显示旧字体别名时，查看最终替换结果；别名未变不等于中文字体未生效。
- 按最终部署文本所需字符检查 glyph，并保留游戏使用的字体名称与加载关系。字体许可随交付保存。
- 主字体缺少特殊符号时，可以把这些码点保留到支持它们的字体，其余文本使用目标语字体。
  [FontGroup](https://www.renpy.org/doc/html/text.html#font-groups)的范围顺序影响字符选择；检查
  合并后的覆盖与实际加载，不能只对主字体计算“缺口 0”。
- 保留独立 emoji 字体及既有特殊字符映射。不要盲目替换全部字体属性，也不要借用另一款游戏的
  固定码点列表。

核对有效语言与游戏已有语言选择机制，保留用户的持久化设置；不能用每次启动清空 persistent
或强制改写偏好来证明中文已启用。字体加载和 glyph 覆盖通过仍需人工观察换行、裁切及符号形状。

## 从最终部署清单生成补丁

用户要求独立补丁时执行。仅要求继续翻译或固定经验时，不额外开始压缩与发布。

1. 记录适用游戏版本与原件基线，确认当前发行副本采用本轮 WriteBack 和消费者接入。依据有效部署
   清单选择 payload；源脚本在 `.rpa` 内时，新增加的 loose 脚本仍可能是必需覆盖项，不能只看
   物理目录内“修改了哪些既有文件”。
2. 收纳所需译文、消费者脚本、语言/字体接入及字体。若包含 `.rpyc`，由匹配引擎从最终 `.rpy`
   编译并核对配对；不把其他版本的旧编译文件或诊断钩子带入补丁。
3. 提供安装位置、适用版本、文件清单、哈希、字体许可和卸载/回退说明。ZIP 根目录与安装方法一致，
   例如 `game/` 合并到 EXE 所在目录。已有同名修改先备份；卸载只处理清单内新增项或恢复覆盖项，
   不删除整个 `game`、`tl` 或用户存档。
4. 排除无关本体资源、游戏 EXE、ATT 程序、配置、凭据、数据库、日志、缓存、存档及工作脚本。
   必需的完整消费者脚本属于 payload，不能因其中含未改动代码而遗漏。
5. 校验实际 ZIP 的文件集合、重复/不安全路径、CRC 与逐条内容哈希，确认与 staged payload 一致。
   文件存在、压缩成功或可以打开 ZIP 均不足以证明完整安装。

## 干净安装与验收边界

从只读原件复制测试基线到工作目录，先核对版本及关键资源，再从**交付的实际 ZIP**安装，
而不是直接复制 staging。使用匹配引擎验证编译、翻译缺口、有效语言、字体及关键消费者来源。
需要执行 CLI 时，先核对初始化代码的副作用和该版本的存档重定向方式，保持测试与用户游戏状态隔离。

安装前按 manifest 校验全部 payload；编译后重点回读源脚本、字体及有效结构。引擎可能重新生成
`.rpyc`，不能把合法重编译后的哈希变化直接判为 ZIP 损坏。

静态产物、引擎编译/初始化、人工实际游玩分别验收：

- 静态产物：来源映射和部署清单一致，原件及非目标资源未变。
- 编译/初始化：脚本编译成功，译文查找和有效字体成立；缺失计数只覆盖引擎登记项。
- 人工实机：启动、菜单、对话、自定义界面、布局和存读档；未执行就明确未验证。

用户中止窗口验证后，不换工具继续同一次测试。后续授权的补丁静态验证可独立完成，仍保留实机
未验证的结论。收尾记录任务进程状态、测试副本是否保留；清理只涉及本轮创建且边界已确认的目录。
