# Ren'Py 提取与显示消费者

在初次转换、补提取或截图漏翻定位时读取。ATT 的输入、状态和输出契约始终以包内 Generic 文档为准；
以下方法只负责 Ren'Py 外部适配。

## 原生模板与覆盖对账

Ren'Py 原生对话翻译块和菜单/字符串表是两类来源。使用模板前，核对实际加载脚本与模板来源，
并记录已覆盖与失败范围；不能仅对已存在模板做计数，再把它当作游戏全文。
模板生成方式见 [Ren'Py 翻译文档](https://www.renpy.org/doc/html/translation.html#generating-translation-files)，
实际命令与选项以游戏所带版本为准。

- 对话保留引擎的翻译块身份、说话者、属性、voice 等非正文结构。空目标模板须从对应源节点或源注释
  恢复原文，不能把模板中的空目标作为待翻译正文。
- 字符串保留 `old` 的准确值和上下文标签，将 ATT 结果写入相应 `new`。不要翻译作为查找键的 `old`，
  也不要按目标文件行号或仅凭“相同原文”绑定对话位置。
- 转换使用该语法对应的解析或可靠词法定位，处理转义、引号、相邻字符串、多行和注释。不能对整个
  `.rpy` 用无边界字符串替换；解析失败留作未决，不跳过后仍报告完整。
- 全部对应位置须能从源结构追到 JSONL，再从输出回到最终脚本；重复原文、重复标签和多行值是
  往返验证需要覆盖的不同结构边界。

相同源字符串在原生字符串表中共享查找结果。需要不同译法时，先确认显示位置的上下文区分方式，
例如 [Ren'Py 的上下文标签](https://www.renpy.org/doc/html/translation.html#menu-and-string-translations)；
不能只建立两个 ATT ID 就假定游戏能选择两种译文。保留既有 `{#...}` 身份，不以去重方便删掉它。

## 模板之外的界面

从真正显示文字的调用反查来源：screen 的 `text`/`textbutton`、`show text`、`Text(...)`、
角色名、Python 生成字符串及游戏自定义显示组件。优先核对反馈涉及的启动 label/screen 和同类来源。
字段名、文件名相似不等于实际调用相同；变量、资源路径、按钮 action 和比较键不自动属于正文。

原生生成器会识别菜单及 `_()` 标记的字符串。`_()` 标记与显示阶段的翻译是不同环节，见
[Ren'Py 字符串翻译函数](https://www.renpy.org/doc/html/translation.html)。
对缺少模板/查找接入的硬编码值，可由适配器在保持游戏逻辑的前提下标记可翻译值并补齐字符串表；
不是每个字符串字面量都应该机械包上 `_()`。

例如，启动提示采用 `show text`，而确认按钮采用已有 screen 字符串；按钮已汉化只证明按钮来源。
返修须核对提示本身的显示查找，保留字体大小、位置、暂停、按钮动作和文本标签，并检查同类
`show text` 调用。这里只描述结构，不要求为所有游戏增加统一启动脚本。

## 新来源与占位符

补提取添加独立、稳定的来源身份，避免改变既有 Group 的语境。重新 Extract 后按现行状态规则
核对受影响译文，再消费新 WriteBack。不能承诺所有结构变化都保留 Current；具体边界见
[Generic Extract](../../../docs/generic/extraction.md)。

重复标签不能只校验集合。按实际 ATT Placeholder 约定检查 token 的次数和顺序，再检查恢复后的
插值与标签配对。自定义文本标签、`[[`/`{{` 等转义与动态插值分别按实际消费者确认，不能为降低
拒绝率移除保护或覆盖整个正文。

空槽、控制格式和源语残留的启发式告警先按实际结构核对。空槽不等于整条正文为空；结构排除误报
不等于语义审校或排版实测通过。可保留明确的 QA 未验证项，不把它们伪装成确定错误或通过。

## 引擎检查与有效来源

使用匹配引擎的编译和翻译缺失计数，选项参照
[Ren'Py CLI](https://www.renpy.org/doc/html/cli.html#translate)。`translate <语言> --count` 只检查引擎
识别的翻译项，不证明模板之外的界面覆盖。计数与外部来源对账缺一不可。

[编译命令](https://www.renpy.org/doc/html/cli.html#compile)可能删除没有源文件的孤立编译脚本。
对包含仅 `.rpyc` 的游戏，先检查本版本的保留选项（支持时使用 `--keep-orphan-rpyc`）或在隔离副本
验证其它保留方式。不要直接 force recompile 后发现脚本丢失才补救，也不任意清空整个缓存目录。

同名 screen 或归档和 loose 脚本并存时，核对最终加载定义及消费者查找结果；若需版本专用初始化
诊断，记录该版本与验证范围，不能把内部注册表形状升级为跨版本公共 API。测试钩子不进入最终补丁。
源脚本部署正确、`.rpyc` 编译成功、初始化正确和窗口显示正确分别报告。
