# 接入 MV 透明胶囊姓名牌

目标是在汉化游戏副本中把人物姓名从正文层级分离，采用 `assets/ATT_NamePlate.js` 的绘制方式
显示为宽度自适应的透明胶囊姓名牌，并保留当前消息系统的台词、控制符和剧情流程。默认姓名牌
使用透明背景、白色细边、白字和深色文字描边；左边缘与对话框对齐，下边缘贴合对话框上沿。

`assets/ATT_NamePlate.js` 提供姓名牌绘制模板。Agent 依据当前游戏的姓名来源和消息生命周期，
选择改造现有姓名窗口或接入独立姓名牌，并把连接代码写入当前汉化副本。

## 调查并选择接入方式

1. 确认目标为 RPG Maker MV，并读取 `www/js/plugins.js` 中实际启用的消息插件及加载顺序。
2. 从一条真实人物对话追踪到 `Game_Message.add` 和 `Window_Message`，确定姓名由事件文本、转义码、
   插件字段还是自定义场景脚本提供。
3. 当前消息系统已有姓名窗口时，沿用它的姓名解析、定位和生命周期并替换绘制样式；当前消息系统
   只有姓名数据时，使用随附模板接入独立姓名牌。
4. 在拥有姓名规则的插件或函数处取得权威姓名，把姓名交给选定姓名牌，正文继续交给原消息窗口；
   同步当前游戏实际使用的显示、隐藏、定位、关闭和对话回看行为。
5. 目标游戏确实使用 `TS_ADVsystem` 的 `[姓名]正文` 格式时，复用随附实现；其余游戏在汉化副本中
   编写连接当前姓名来源的适配代码，使每份实现对应一套经过确认的消息路径。

## 写入汉化副本

1. 使用独立姓名牌时，把 `assets/ATT_NamePlate.js` 复制到汉化副本的
   `www/js/plugins/ATT_NamePlate.js`；沿用现有姓名窗口时，把模板的胶囊绘制方式应用到该窗口。
2. 使用独立姓名牌时，在 `www/js/plugins.js` 中启用它并让它在所连接的消息插件之后加载；沿用现有
   姓名窗口时，保留当前加载关系并确认承载该窗口的插件已启用。
3. 使用独立姓名牌时，通过插件参数设置字体、字号、最小宽度、最大宽度和高度；沿用现有姓名窗口时，
   在当前实现中设置对应尺寸。`GameFont` 会沿用汉化副本已经配置的中文字体。
4. 应用透明背景、白色细边、白字和深色文字描边；让姓名牌左边缘与对话框左边缘对齐，并让两者边框
   贴合。消息框位于屏幕顶部且上方空间不足时，让姓名牌贴合消息框下沿。
5. 任务发起者明确给出其他视觉要求时，在同一绘制实现中应用该要求，并继续保持姓名牌与对话框的
   跟随关系。
6. 让人物对话设置姓名，让旁白使用空姓名；长姓名由插件在对话框宽度内自动扩展。
7. 把插件与 `plugins.js` 纳入当前汉化副本和最终封包，原版游戏继续作为只读基线。

## 验证交付

- 使用 `node --check` 检查插件语法；使用独立姓名牌时，解析 `plugins.js` 确认它已启用且位于所连接的
  消息插件之后；沿用现有姓名窗口时，确认承载窗口的插件已启用并保留当前加载关系。
- 静态核对原消息系统判定需要显示姓名的对话由选定姓名牌显示一次姓名，正文保留原有缩进、换行、
  语音和控制符。
- 核对姓名牌背景透明、边框和文字清晰，并随消息框保持左边缘对齐和边框贴合。
- 向任务发起者交付人工实机检查项：普通人物对话、旁白、连续换人、长姓名、上下位置消息、
  对话回看及隐藏消息窗口。
- 由任务发起者人工启动游戏完成实机验证；根据截图和触发场景调整同一插件参数或姓名连接点。
