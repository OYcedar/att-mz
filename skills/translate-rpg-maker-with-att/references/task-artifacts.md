# ATT 翻译任务产物规范

本文件只管理任务负责人和协作者自己创建的清单、输入副本、备份、证据和 QA 材料。ATT 的
项目布局、数据库、日志、运行方案、候选、发布和恢复产物仍完全由本次实际发布文档负责。

## 区分产物所有者

| 产物 | 所有者与用途 | 任务负责人可以做什么 |
|---|---|---|
| 冻结 `source/`、`project.db`、当前 `write_back/` | ATT 的来源、项目状态和当前发布结果 | 按现行文档只读核对或通过 ATT 命令修改；不手改、不放人工文件 |
| `logs/`、`task-records/` | ATT 的诊断材料 | 保留原位，按 RunId 和原路径引用；不把它们当恢复或提交权威 |
| `.att-locks`、candidate、stage、backup、journal | ATT 的锁、发布和恢复材料 | 不创建、不移动、不改名、不清理；只按实际诊断处理 |
| 任务清单、采用输入、修改前副本、报告、截图、隔离验证材料 | 任务负责人管理的协作材料 | 放在安全任务根，使用唯一名称，并记录它们证明的事实 |

人工材料不得使用 `source`、`write_back`、`logs`、`task-records`、`candidate`、
`project.db` 或 `.att-locks` 等会和 ATT 产物混淆的名称。

## 选择安全任务根

优先使用用户明确指定、能够持续保存的任务根。任务根必须位于以下位置之外：

- 原游戏和游戏实际加载目录；
- ATT 发布目录和 Skill 安装目录；
- 配置解析出的整个 `projects.root`，包括任何项目工作区；
- ATT 的 `source`、`write_back`、日志、任务记录和内部恢复位置；
- 用户最终交付目录；
- 系统临时目录。

没有安全位置时先请用户指定。不得为寻找旧清单扫描整块磁盘。

推荐让每个独立任务使用自己的目录：

```text
<用户认可的工作根>/<engine>-<safe-project>-<task-short-id>/
  ATT-翻译任务-<engine>-<safe-project>-<YYYYMMDD>[-NN].md
  artifacts/
    inputs/
    backups/
    evidence/
    qa/
    scratch/
```

只创建当前工作实际需要的子目录，不预建空目录：

- `inputs/`：本任务采用或准备采用的 Rules、Terminology、Placeholder、Prompt、Lua 等；
- `backups/`：修改前逐字副本；
- `evidence/`：调查结果、只读导出、经过处理的短摘录和目录差异报告；
- `qa/`：截图、游戏运行记录和隔离验证材料；
- `scratch/`：尚未成为 TODO 证据、可以重建的实验材料。

`safe-project` 只用于文件识别：把 Windows 禁止的文件名字符、控制字符和结尾空格或句点
替换为 `_`，并在创建前检查大小写不敏感冲突。任务清单内部的绝对项目工作区才是权威身份。

## 文件命名和不可变记录

除任务清单外，人工产物采用：

```text
<TODO-ID>-<purpose>-<YYYYMMDD-HHMMSS>[-<RunId-or-sha256-short>].<ext>
```

示例：

```text
EX-04-extract-rules-20260729-143012-a31f9c20.toml
TR-07-terminology-impact-20260729-151844-2f7c3a91.md
WB-03-game-menu-20260729-174206-6c1e6ee2.png
```

规则如下：

- `purpose` 使用简短、稳定、能说明内容的 ASCII 名称；
- 时间使用任务所在地的实际时间，格式固定为 `YYYYMMDD-HHMMSS`；
- ATT 命令产物优先加入 RunId；输入或报告可加入 SHA-256 前 8–12 位；
- 任务清单记录完整 SHA-256，不用短前缀代替内容身份；
- 不用 `latest`、`new`、`final`、`final2` 或只有 `backup` 的含糊名称；
- 同一路径不得由两个协作者共同写入；
- 已完成 TODO 引用的文件不得覆盖、改名或删除；重新检查时创建新文件；
- 工作中的输入若要修改，在新路径生成下一份，不让历史 TODO 继续引用已改变内容。

大段日志、模型正文和 ATT 任务记录保留在产品原位置。只有审查确实需要短材料时，才在
`evidence/` 保存按实际敏感信息规定处理的摘录，并写明原 RunId、原文件、位置和摘录目的。

## 每条证据应记录什么

任务清单中的证据至少说明：

- 绝对路径或 ATT RunId；
- 文件 SHA-256，或数据库查询的项目身份和观察时间；
- 使用了哪一轮来源、配置、Prompt 或脚本；
- 该证据具体证明什么；
- 它是权威项目状态、ATT 诊断材料，还是人工 QA 结果。

文件存在、截图存在或日志中出现“成功”不能单独证明数据库提交、目录发布或游戏实际加载
正确内容。

## 配置、Prompt、Rules 和 Lua

这些资源有不同生命周期。精确行为由实际 `docs/runtime/cli.md`、
`docs/runtime/configuration.md`、`docs/rpg-maker/rules.md`、`prompts.md` 和 `lua.md`
定义；任务材料只记录对复现和审查有用的身份。

- **配置**：记录实际命令 cwd、配置绝对路径、SHA-256，以及本次命令实际消费的解析后
  绝对根。先按实际 `docs/runtime/chat-completions.md` 的唯一规定判断逐字副本能否保留；
  若副本会复制其中规定的敏感值，不得把它放入任务目录，修改前必须由用户确认另一个安全
  且可恢复的权威来源，并且清单只记录该来源的身份。没有可恢复来源时停止修改。替换敏感
  值的副本只能作为差异证据，不能声称是备份。允许保留的配置副本换目录后会重新解释相对
  路径，仍不得直接用于 ATT 命令。
- **Rules、Terminology、Placeholder**：成功采用后的项目 canonical 状态由 ATT 负责；
  任务仍保留当时采用输入的逐字副本、原路径和 SHA-256，供审查决策。修改后使用新文件。
- **Prompt**：每轮 Translate 都核对实际 Prompt 根、选中的文件和 SHA-256。共享 Prompt
  的修改可能影响其他项目；没有完整影响和授权时不得修改。
- **Lua 动态加载与直接访问**：阶段 Lua 和独立项目 Lua 都记录主程序解析目录、调用 cwd、
  实际采用的路径来源（`LUA_PATH_5_4`、后备 `LUA_PATH` 或内置默认）、展开后的初始
  `package.path`，以及脚本对
  `package.path`、`package.preload[name]`、`package.loaded[name]`、`package.searchers`
  的相关修改。脚本通过 `os.getenv` 使用的其他环境变量记录变量名、实际采用值及其影响，
  并按本次实际发布目录中 `docs/runtime/chat-completions.md` 的唯一规定处理。每个实际
  文件依赖记录访问方式、最终绝对路径、SHA-256 和继续任务时的可用性；
  没有文件路径的 `package.loaded` 预置值、preload 或自定义 searcher 记录定义来源和
  生产者身份。直接文件修改、进程、网络和私有 SQLite 的记录包含目标、动作、授权和
  执行前后状态，以及验证与恢复办法。依赖很多时，把逐项记录保存为唯一命名的
  `evidence/` 文件，并在任务清单中记录该文件的路径和 SHA-256，不把全部内容塞进清单
  正文。
  外部依赖可以位于项目、发布目录和任务根之外，不要求为了保存证据而复制或移动它；无法
  保留或重新访问时明确记录未验证风险。
- **阶段 Lua**：分别记录 Extract、Translate、WriteBack 采用的主程序身份。ATT 保存主
  程序正文不表示它保存了 `require`、`loadfile`、`dofile`、`io`、`os` 等动态依赖。
- **独立项目 Lua**：每次从显式脚本读取，不属于阶段快照。脚本、参数、ATT 返回结果和
  权威状态复读共同作为提交证据。

除上述配置限制外，修改前副本应逐字保存，并记录原绝对路径、备份路径、修改前
SHA-256、复制时间和所属 TODO。不要通过重新序列化生成“备份”。

## 输出、差异和 QA

`write_back` 会被后续 WriteBack 或来源变化后的 Init 替换，不能作为长期证据目录。需要
保留某轮结果时，把它复制到用户认可且位于 ATT 工作区之外的位置，并记录项目身份、
WriteBack RunId、来源指纹或目录树身份。

- 差异报告放在两个被比较目录之外；
- 截图名称包含 TODO、场景、时间和输出身份；
- 隔离游戏副本位于原游戏、ATT 工作区和最终交付目录之外，并记录所用 WriteBack；
- `write_back` 不是完整游戏包；隔离验证必须使用用户确认的完整游戏基线和项目部署方法，
  并记录内容树与真实加载目录的映射；
- 后续运行不得覆盖已经被完成 TODO 引用的交付副本或 QA 材料。

大型隔离副本虽然可以重建，但删除前要确认截图、差异和运行结果已经保存，且没有完成
TODO 仍引用该副本。最终回复说明保留和清理了哪些路径。

## 协作者写入和清理

任务负责人委派时指定：

- 对应 TODO；
- 只读范围或可写的精确目录/文件；
- 不得覆盖的已有文件；
- 是否允许运行 ATT 或发出外部请求；
- 返回的产物清单、完整 SHA-256 和未确认事实。

协作者不得创建第二份任务清单，不得修改 ATT 自有产物，也不得写其他协作者的输出路径。

只可清理 `scratch/` 中未被 TODO、决定或交付记录引用的材料。清理前解析并核对绝对目标
确实位于当前任务根内；不得用未展开变量、宽泛 glob 或相对路径触及原游戏、ATT 工作区、
发布目录或最终交付目录。其他任务材料默认保留，是否清理由用户或任务计划明确决定。
