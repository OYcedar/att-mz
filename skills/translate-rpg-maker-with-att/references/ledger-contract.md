# 实体任务账本契约

本文件定义唯一任务账本的位置、结构、状态、证据、变更、恢复和完成语义。新建、恢复、
改变结构、分派子 Agent 或宣告完成前完整读取。

## 1. 唯一文件与生命周期

- 每个翻译任务只使用一个账本，不另建阶段清单、隐藏 TODO 或平行状态文件。
- 默认路径为 `<任务根>/att-tasks/<YYYYMMDD-HHmmss>-<引擎>-<项目名>.md`。
- 任务根必须是稳定、由操作者控制并长期保留的翻译工作区。把绝对路径写入任务契约。
- 不得把账本放进原始游戏内容树、ATT 受管项目根、候选或最终输出、封包暂存、`tmp`、
  缓存、运行日志、`task-records` 或 Skill 安装目录。
- 文件名中的非法路径字符替换为 `-`；冲突时追加 `-02`、`-03`。创建后不改名，文件 stem
  作为任务 ID。
- 同一 ATT 项目同时最多有一个未完成账本。创建前搜索；同一目标的续作、补充和新证据
  继续原文件。
- 真正不同的新目标只有在旧任务完成、取消或明确移交后才新建账本。
- 完成、取消或整体替代后原地保留，不自动移动、删除、覆盖或提交到游戏项目。

## 2. 创建时机与固定结构

Agent 先只读了解整个项目并制定宏观方案，再亲自从
[任务账本模板](../assets/task-ledger-template.md)创建文件。任务账本必须严格保留以下顺序：

1. 唯一一级标题；
2. `整体方案`；
3. `任务契约`；
4. `项目全局事实与影响分析`；
5. `阶段总览与当前恢复入口`；
6. `1. 解包（UNP）`；
7. `2. 提取（EXT）`；
8. `3. 翻译（TRN）`；
9. `4. 写回（WBK）`；
10. `5. 封包（RPK）`；
11. `证据登记`；
12. `方案与变更记录`；
13. `阻塞、剩余风险、恢复与移交`；
14. `最终完成判断`。

整体方案必须先用人话说明完整路线、机制选择、跨阶段依赖、风险和验证方法。不得先生成
大量 TODO 再倒推出方案。

创建时一次写出五阶段及每阶段三个固定责任。项目专属 TODO 只写当前证据支持的内容，
进入阶段前再根据最新事实细化。

## 3. 稳定 ID 与固定责任

使用以下前缀：

| 对象 | 前缀 |
|---|---|
| 解包 TODO | `UNP-*` |
| 提取 TODO | `EXT-*` |
| 翻译 TODO | `TRN-*` |
| 写回 TODO | `WBK-*` |
| 封包 TODO | `RPK-*` |
| 证据 | `EV-*` |
| 方案或事实变化 | `CHG-*` |

每阶段初始固定：

- `XXX-001`：阶段宏观责任；
- `XXX-002`：输入、适用性、依赖和全局影响核实门；
- `XXX-003`：结果、证据、缺口和下游交接验收门。

项目专属 TODO 从 `XXX-004` 起递增。ID 在整个文件内唯一，创建后不复用、不重排、不改
前缀。责任阶段、目标、范围、依赖或完成条件改变时，把旧项标为 `SUPERSEDED` 并创建
新 ID；拆分和合并同理。

## 4. TODO 格式

每项使用：

```markdown
- [ ] `TRN-004` `[TODO]` 核实 Placeholder 的完整消费者范围
  - 父项：TRN-001
  - 依赖：TRN-002
  - 完成条件：按 kind 与 Owner 列出实际消费者，并建立修改前跨度基线
  - 执行者：主 Agent
  - 最近结果：NotRun
  - 结果与证据：—
  - 剩余与恢复入口：—
```

标题必须描述可验收责任；完成条件不能只写“确认正常”。每次执行后立即更新最近结果、
证据、剩余和恢复入口。

条件状态还必须增加：

- `N/A`：`适用性核实：<结论与 EV 引用>`
- `BLOCKED`：`阻塞原因：<事实>`、`已确认状态：<事实>`
- `SUPERSEDED`：`替代项：<一个或多个 TODO ID>`
- `CANCELLED`：`取消依据：<用户决定与 EV 引用>`

已有终态项的标题、责任、完成条件、结果和证据不得倒改。新事实推翻旧结论时保留旧项，
追加 `CHG-*`，并创建新的核实或返工 TODO。

## 5. Agent 责任状态

状态使用闭集：

| 状态 | 责任含义 | checkbox |
|---|---|---|
| `TODO` | 已确认需要完成，尚未开始 | `[ ]` |
| `DOING` | 当前正在执行 | `[ ]` |
| `BLOCKED` | 责任仍需完成，但存在明确阻塞 | `[ ]` |
| `DONE` | 按完成条件履行并有有效证据 | `[x]` |
| `N/A` | 经核实对本任务确实不适用 | `[x]` |
| `SUPERSEDED` | 被一个或多个新 TODO 正式替代 | `[x]` |
| `CANCELLED` | 因用户改变范围或撤销授权而终止 | `[x]` |

- `DONE` 必须引用至少一条当前有效 `EV-*`。
- `BLOCKED` 必须说明阻塞原因、已知终态和安全恢复入口。
- `N/A` 必须有适用性证据；不能用于隐藏困难任务。
- `SUPERSEDED` 必须指向全部替代项，替代链不得循环。
- `CANCELLED` 只用于用户改变范围或授权，技术失败不能取消责任。

## 6. ATT 执行结果

执行结果与责任状态分开，使用：

`NotRun`、`Succeeded`、`Partial`、`Unavailable`、`Failed`、`Cancelled`、
`OutcomeUnknown`。

- `Partial`、`Unavailable` 或 `Failed` 不能支持要求完整业务结果的 TODO 或验收门
  `DONE`。
- 只负责诊断或采证的 TODO 可在取得预定证据后 `DONE`，但必须保留观察到的失败结果。
- `OutcomeUnknown` 使相关责任进入 `BLOCKED`：保留现场，停止同类副作用，先核实是否已经
  提交或发布。
- 已确认提交的有效部分进展继续保留，不伪装成全成或全败。

## 7. 不适用阶段

五阶段标题永远保留。

1. 先让 `XXX-002` 核实不适用的事实、边界和下游影响，并以 `DONE` 结束。
2. 把 `XXX-001` 标为有证据的 `N/A`。
3. 让 `XXX-003` 以 `DONE` 验收该结论。

固定门自身不得标为 `N/A`、`SUPERSEDED` 或 `CANCELLED`。例如用户明确要求并验收 loose
tree 时，封包可以不适用；“ATT 没有通用封包命令”不能证明用户不需要封包。

## 8. 证据登记

每条证据采用三级标题：

```markdown
### EV-001

- 类型与观察时间：文件；2026-07-28 23:51 +08:00
- 来源定位：绝对路径、命令、日志事件、查询、哈希、产物或用户决定
- 直接观察：实际看见的事实
- 支持或否定：TRN-004、CHG-001
- 适用范围：受支持结论的准确边界
- 当前有效性：有效
```

- 保存定位和直接观察，不复制海量日志。
- 不写入敏感值。敏感信息边界只引用
  [Chat Completions 现行规格](../../../docs/runtime/chat-completions.md)，不得自行扩展。
- 退出码不能单独证明业务完成。
- Agent 自述、子 Agent 自述和账本自身不能作为项目结果证据。
- 证据失效时保留原观察，把有效性改为 `失效（CHG-xxx）`；不要篡改原事实。

## 9. 方案与变更记录

发生宏观方案变化、配置修改、TODO 拆分/合并/替代/取消、责任阶段变化、依赖变化或上游
改变导致下游结论失效时，追加：

```markdown
### CHG-001

- 时间：2026-07-28 23:55 +08:00
- 配置变更：否
- 触发证据：EV-001
- 原方案或判断：……
- 新方案与理由：……
- 替代方案、保留行为与代价：……
- 受影响的 TODO、阶段与完成声明：……
- 新增、替代或重新核实 TODO：……
- 安全恢复入口：……
```

配置变更为 `是` 时额外填写：

```markdown
- 根因：……
- 现实消费者与影响范围：……
- 修改 TODO：……
- 修改前验证 TODO：……
- 修改后验证 TODO：……
```

记录按时间追加，不改写成“从未发生过”。上游变化不抹掉旧 `DONE`；变更记录说明其不再
支持当前完成判断，并建立新的重验 TODO。阶段总览只引用最新有效验收。

## 10. 恢复与多 Agent

恢复时：

1. 完整读取账本及引用证据；
2. 核对实际项目状态，项目事实优先于账本声明；
3. 判断中断的 `DOING` 是否产生副作用，无法确定则进入 `OutcomeUnknown`/`BLOCKED`；
4. 用新变更记录修正矛盾，不静默重写历史；
5. 从“当前恢复入口”继续，不重复有效证据已经证明的工作。

主 Agent 是唯一写入者。委派前创建 TODO ID 并限定调查范围；子 Agent 不修改账本，只返回
TODO ID、观察、实际改动、证据、结果、不确定性和建议重开项。主 Agent 核验后亲自回填。
不要建立锁文件、第二份 JSON、子 Agent 分表或其他竞争状态源。

## 11. 完成门

只有同时满足以下条件，才能写入最终完成声明：

- 五阶段当前宏观责任均为 `DONE` 或有证据的 `N/A`；
- 每阶段初始固定门及阶段总览所指的最新重验门均为 `DONE`；
- 不存在 `TODO`、`DOING` 或 `BLOCKED`；
- `SUPERSEDED` 可追到有效替代项，`CANCELLED` 有用户依据；
- 所有配置变更完成完整影响范围验证；
- 最终产物、必须保持行为和用户成功条件有当前有效项目证据；
- 剩余风险确实位于任务停止线之外。

最终交付前从 `SKILL.md` 所在目录解析并执行
`scripts/validate_ledger.py <账本> --final`。校验器只能证明结构和引用关系，不能证明
证据真实或业务完成；主 Agent 仍对语义判断负责。
