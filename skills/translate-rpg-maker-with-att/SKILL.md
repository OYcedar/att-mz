# 用 ATT 完成 RPG Maker 翻译

## 基本要求

如果你直接处理整个用户任务并负责最终交付，你就是任务负责人，必须亲自创建并持续更新
一个 Markdown 任务清单。如果你只收到其中一个 TODO 的委派，你是协作者，不得修改任务
清单，只返回该 TODO 的结果和证据。以下流程由任务负责人执行；协作者只执行明确委派的
TODO。

任务清单记录：

- 对整个项目的理解和计划；
- 解包、提取、翻译、写回、封包五个阶段的工作；
- 每个 TODO 的实际结果和证据；
- 计划或配置为什么改变、影响了什么、需要重新检查什么；
- 中断后应该从哪一步继续。

任务清单说明实际做了什么、为什么这样做以及如何确认结果。ATT 的数据库、日志、
`task-records` 和输出文件仍然记录产品实际发生了什么；它们不能互相替代。

五个阶段必须始终保留：

1. 解包
2. 提取
3. 翻译
4. 写回
5. 封包

每个阶段固定保留阶段总任务、开始前检查和完成检查。翻译阶段还固定保留术语检查
`TRN-004`。其他 TODO 根据项目事实增补、拆分、替换或调整顺序，不能照模板机械执行。
完成一项就立即更新一项，不得在工作结束后凭记忆补写。

## ATT 文档是必需输入

先完整读取 [ATT 文档入口](../../docs/README.md)，再按其中的链接读取本任务需要的现行文档。
CLI、配置、Lua API、数据格式、状态、错误和发布行为只由这些文档定义。本 Skill 只规定
执行方法，不重复保存产品说明。

说明产品行为时沿用文档中的原生名称，例如 TaskBlock、Managed API 和 `OutcomeUnknown`。
没有准确中文对应的名词直接使用原名，不自造中文简称、比喻或只有本 Skill 才使用的术语。

在任务清单中记录：

- `实际使用的 ATT`：本任务实际调用的程序绝对路径，以及文件哈希、对应的 Git 提交 ID
  或构建版本；
- `ATT 文档版本`：实际读取的 `docs` 根绝对路径，以及对应的 Git 提交 ID 或目录内容
  哈希。

开始修改项目之前，必须确认程序和文档属于同一份现行实现。缺少必要文档、文档无法完整
读取或二者无法对应时，停止修改；已有任务清单则把当前 TODO 设为 `BLOCKED`，写明已经
确认的事实和下一步。不得用旧对话、旧 Skill、源码猜测或试错修改代替现行文档。

每个阶段的 `XXX-002` 和术语检查 `TRN-004` 都要填写 `参考文档`，列出本次实际完整读过的
Markdown 文件和相关章节。修改 Rules、Placeholder、术语、Prompt 或 Lua 时，对应
`CHG-*` 也要填写 `参考文档`。

## 开始任务

1. 完整读取 [任务清单规则](references/task-list-rules.md) 和
   [项目调查与配置修改](references/project-review-and-changes.md)。
2. 只读调查用户目标、游戏实际加载位置、发行结构、ATT 项目状态、现有配置、文本来源、
   已有译文和输出。
3. 按 [五个阶段的工作要求](references/stage-checks.md) 形成覆盖整个项目的方案。局部报错
   只能作为调查起点，不能直接决定方案范围。
4. 在稳定的任务目录中搜索同一 ATT 项目的未完成任务清单：
   - 找到时，完整读取并与项目实际状态核对后继续；
   - 没有时，先完成整体方案，再亲自从
     [任务清单模板](assets/task-list-template.md)创建唯一文件。
5. 一次写出五个阶段的固定 TODO，只增加已有事实支持的项目专属 TODO。
6. 从本 `SKILL.md` 所在目录解析脚本绝对路径并运行：

   ```powershell
   uv run --no-project python "<本 Skill 目录>/scripts/validate_task_list.py" "<任务清单绝对路径>"
   ```

只有任务清单通过检查、当前修改有对应 TODO、相关文档已经读取且本阶段的开始前检查已经
完成，才能修改项目。

聊天内计划、内置计划工具、项目日志、`task-records`、协作者报告和额外 JSON 文件都
不能替代这份任务清单。

## 每次执行 TODO

采取实际行动前：

1. 读取整体方案、当前阶段、下一步、相关 TODO、参考文档和仍待处理的变更。
2. 确认 ATT 程序和文档版本没有变化。
3. 确认本次行动已有 TODO，写清完成标准、允许修改的范围和需要保存的证据。
4. 执行完成该 TODO 所需的最小工作。
5. 立即记录实际结果、证据位置、尚未完成的内容和下一步。
6. 根据项目实际状态完成本阶段的完成检查；发现更早阶段的问题时返回那个阶段，并为受
   影响的后续结果建立新的检查 TODO。

命令退出码、请求成功、日志存在、目录存在或聊天中的完成声明都不能单独证明任务完成。证据中
必须保留 ATT 实际返回的结果、错误、数据库状态、文件差异或发布结果。

ATT 程序、`docs` 根或其身份变化时，先停止新的修改，增加 `CHG-*`，记录旧值、新值、
受影响的 TODO 和需要重新执行的检查；重新阅读相关文档后才能继续。

## 修改项目配置

用户授权执行翻译、修复或交付时，可以修改任务范围内且可以恢复的 Rules、
Placeholder、术语、Prompt 和项目 Lua。用户只要求分析、解释或建议时保持只读。

每次修改前都按
[项目调查与配置修改](references/project-review-and-changes.md)执行：

- 先读取当前产品文档；
- 查明原因、负责该含义的组件、所有实际使用位置和影响范围；
- 保存修改前结果；
- 比较可行方案会保留和改变什么；
- 分别建立修改前检查、修改和修改后检查 TODO；
- 对所有受影响内容比较修改前后结果；
- 为已经不再成立的后续结论建立新的检查 TODO。

修改 Placeholder 时，不能只测试触发报错的一个字符串。必须检查所有实际文本来源和使用
位置，比较修改前后的命中、未命中、错误命中、重叠和保护范围。字段和匹配规则只从
[Rules 文档](../../docs/rpg-maker/rules.md)读取。

不得自行改变 API key、模型或费用选择、目标语言、外部服务、用户要求的交付范围，也不得
执行不可恢复的操作。缺少这些决定时暂停并询问用户。

## 术语

正式批量翻译前必须完成 `TRN-004`。先完整读取
[术语文档](../../docs/rpg-maker/terminology.md)。

MV/MZ 的特殊字段和引擎结构只用于发现可能重要的术语。最终判断必须检查任务范围内全部
玩家可见文本以及运行时实际读取这些文本的代码或数据，说明候选词在不同上下文中的含义、
采用或排除的理由，并验证最终术语文件的正确命中、漏掉内容和错误命中。

当前 Extract 结果不能自动视为全部游戏文本；发现遗漏的文本来源时返回提取阶段。没有
值得固定的术语时，也要用完整调查结果和证据明确记录“没有可用术语”，不能直接跳过。

## Lua 选择

先完整读取 [RPG Maker 文档入口](../../docs/rpg-maker/README.md) 和
[Lua 文档](../../docs/rpg-maker/lua.md)，需要示例时再读取
[Lua Cookbook](../../docs/rpg-maker/lua-cookbook.md)。

根据现行文档比较 Managed API 与低级 API，再选择能够完整表达当前文本关系的接口。
Managed API 不是强制选择。任务清单必须记录选择依据；若选择低级 API，还要记录高级接口
缺少的具体能力、Lua 按文档需要自行完成的工作和验证方法。接口能力、调用顺序和是否存在
自动降级只以产品文档为准，不能凭记忆补充。

## 中断、继续和协作

任务中断、上下文压缩或交接后，先完整重读任务清单，再核对 ATT 程序、文档版本和项目
实际状态。发现不一致时增加 `CHG-*`，不要静默改写旧记录。若某次写操作是否生效无法确认，
保留现场、停止重复操作，并按现行文档确认结果。

任务负责人是任务清单的唯一写入者。把工作委派给协作者之前，先建立 TODO ID。协作者只
返回该 TODO 对应的观察、实际改动、证据位置、结果、不确定性和建议。任务负责人必须核对
实际文件或状态并亲自更新任务清单，不能直接根据协作者的“已完成”声明把 TODO 写成
`DONE`。

## 完成任务

交付前运行：

```powershell
uv run --no-project python "<本 Skill 目录>/scripts/validate_task_list.py" "<任务清单绝对路径>" --final
```

只有以下条件全部满足，才能写“完成”并向用户交付：

- 五个阶段的当前工作均为 `DONE`，或有证据说明阶段确实不适用；
- 每个阶段当前采用的开始前检查和完成检查均已完成；
- 翻译阶段当前采用的术语检查已完成；
- 没有 `TODO`、`DOING`、`BLOCKED` 或待重新验证的变更；
- 每次配置修改都完成修改前检查、修改和修改后检查；
- 用户目标、必须保持的行为和最终文件都有当前仍适用的项目证据；
- 未完成风险确实不在本任务范围内。

最终回复从任务清单汇总实际使用的 ATT、文档版本、改动、验证、交付文件、没有验证的部分
和范围外风险，不依赖临时记忆。
