# 使用 ATT 汉化 RPG Maker

## 使用边界

把本 Skill 作为 ATT 汉化任务的状态路由与执行入口。把现行文档作为产品事实、接口契约和工件验证方法的唯一来源；需要采取动作时按当前流程读取对应文档，不凭记忆补写命令、参数、字段、数据库结构、错误语义或协议。

仅处理通过 ATT 完成 RPG Maker MV/MZ 汉化的工作。遇到 ATT Rust 源码开发、架构设计或普通文本翻译时停止使用本 Skill，改按相应开发约束或翻译目标工作。

## 每次触发

1. 明确本次需要成立的可观察结果，以及已经授权的文件、网络、模型调用、发布和数据库副作用。
2. 先只读检查游戏、ATT 配置、项目工作区、已保存运行方案、候选输出和最近诊断；区分已经持久化的事实、可以从环境发现的事实和必须由使用者选择的事实。
3. 根据真实状态选择当前流程，不因阶段名称或清单顺序机械重跑已经成立的工作。
4. 只为当前目标及其直接依赖建立短任务清单。
5. 在执行每项任务前按需阅读该流程的现行文档；发现文档、实现和测试冲突时，将冲突视为 ATT 项目缺陷，不临时发明兼容解释。
6. 只有掌握真实载体和现行契约后才编写可执行工件；缺少字段、结构或关系证据时先列出采证动作，不用占位名称或猜测语法伪装成可执行定义。
7. 用当前流程的完成证据判断完成、继续或返回责任阶段。

已授权端到端汉化时，在证据允许的范围内自动推进后续流程。只有缺少权威事实、需要扩大成本或范围、或者将产生不可恢复的外部副作用时暂停。

在已授权项目范围内，把相关规则文件、`config.toml` 和 Prompt 视为可根据实际结果调整的项目工件，不把初始内容当作不可变前提。修改必须针对已观察到的问题，并在修改后从最早受影响阶段重跑，以真实结果判断是否保留。

默认只读诊断项目数据库。只有使用者明确要求高级修复时，才可在建立可恢复副本后直接写受管表；写入必须处于事务中，并在提交前后复核当前不变量。

## 自定义规则与经验回流

首次采用或修改自定义规则时，把规则视为待验证假设。消费者既包括运行时代码，也包括按界面和作者约定理解普通显示文本的玩家；没有专用解析分支不表示没有语义协议。先建立不依赖现有正则、已知 marker 或单个解析分支的候选范围，再用规则划分命中与未命中：

- MV 姓名规则以全部标准消息块的第一条 `401` 为候选范围，先归纳全部首行的重复结构和独立标签；专用姓名解析器与普通消息行中的作者约定都要调查，再判断哪些形态承载 Speaker。
- Extract Rules 以已确认运行时消费者读取的全部输入为候选范围，再判断静态路径应提取或排除哪些值。
- Placeholder Rules 以目标 scope 内实际文本和消费者定义的协议为候选范围，再判断哪些跨度应保护或保持自然文本。

对静态可枚举的候选范围全量核对命中、未命中和误命中；无法枚举的部分明确保留为未证实。命令成功和命中数量只证明规则被消费，不证明覆盖完成。

当自定义翻译资源、漏翻或说话人问题已经进入 Standard Translate 调查时，若本轮启用了任务记录，优先读取对应的单个 `task-records/<run-id>/task-000001.md`。在同一文件中核对最终 System/User、合法 Thinking、Assistant、全部重试、逐 ID 验收和真实数据库提交终态；不要从 Provider 外层信封或原始 wire body 猜测这些事实。普通 JSONL 只用于运行级摘要。文件缺失不能证明没有请求，必须结合配置、零任务状态和 stderr 记录健康警告，区分关闭记录、任务未启动和记录失败。

现行敏感信息闭集只有本轮实际选中 LLM Client 的 API key 实际值。Prompt、原文、译文、自定义参数、Thinking、Assistant 和 Provider 正文不因内容类别成为敏感信息；任务记录会精确替换其中出现的 API key 值，不应再隐藏整段正文。

任务产生新的可复用经验时，按知识责任同步：改变触发、状态路由、必读材料、采证方法或停止与完成判断的经验更新本 Skill；规则语义和工件验证方法更新对应现行文档；单个游戏的 marker、字段路径、正则和一次性结论留在项目工件。不要把个案堆成通用清单。

## 流程 0：入口与续作路由

### 进入条件

处理任何适用请求，尤其是已有项目、阶段不明、继续上次工作或需要判断当前责任阶段的请求。

### 必读文档

- 先读[文档总入口](../../docs/README.md)。
- 需要定位共享运行能力的责任文档时，再读[运行时规格导航](../../docs/runtime/README.md)。
- 涉及已保存运行方案、命令终态、退出码或输出通道时，再读[命令行规格](../../docs/runtime/cli.md)。

### 任务清单

- 明确本次目标、游戏引擎、游戏根、项目工作区和允许的副作用。
- 检查配置、项目状态、保存方案、候选输出和最近诊断中已经成立的事实。
- 找出阻止当前结果成立的最早责任阶段。
- 建立只覆盖当前阶段及其直接依赖的短任务清单。

### 完成证据

- 当前责任阶段由项目状态或现实材料支持。
- 已成立阶段没有被无依据地安排重跑。
- 下一项动作所需的事实来源和副作用边界明确。

### 返回位置

状态矛盾、失败影响不明或副作用终态未知时进入流程 6。缺少无法从环境发现的使用者选择时暂停；否则进入对应当前流程。

## 流程 1：调查与初始化

### 进入条件

处理新游戏、新 ATT 项目、需要替换冻结来源，或者引擎、游戏根、语言和三类宽度事实受到质疑的情况。

### 必读文档

- 读[RPG Maker 调查与机制选择指南](../../docs/rpg-maker/README.md)和[Init 规格](../../docs/rpg-maker/init.md)。
- 创建或修正配置时再读[配置规格](../../docs/runtime/configuration.md)。

### 任务清单

- 从实际运行时消费者确认 MV/MZ 版本和精确游戏根。
- 用真实语言资产确认源语言、目标语言及三类宽度事实。
- 按现行规格准备最小配置并执行 Init。
- 核对冻结来源、项目 metadata、原游戏隔离和重复执行收敛。

### 完成证据

- 工作区身份、冻结来源和 metadata 与现实证据一致。
- 原游戏未被修改。
- 使用相同事实重复 Init 得到收敛结果。

### 返回位置

证据不足时继续调查，不猜测默认值。来源或宽度事实错误时留在本流程；既有初始化事实成立时直接进入当前责任流程。

## 流程 2：提取与覆盖证明

### 进入条件

处理首次提取、来源变化、运行时漏文、误收、错组、错误写回边界、recipe 错误或 Claim 冲突。

### 必读文档

- 读[RPG Maker 调查与机制选择指南](../../docs/rpg-maker/README.md)和[Extract 规格](../../docs/rpg-maker/extraction.md)。
- 使用声明式 Extract Rules 时再读[Rules 规格](../../docs/rpg-maker/rules.md)。
- 需要高级只读数据库诊断时再读[SQLite 运行时规格](../../docs/runtime/sqlite.md)。

### 任务清单

- 建立“运行时消费者—语义原子—物理载体—写回位置”的证据关系。
- 根据真实载体选择 Builtin；仅对静态确定路径使用 Rules。
- 执行 Extract；在消费者完整输入域内全量核对自定义规则的命中与误命中，归纳未命中形态，再检查代表性分组与自然顺序。
- 验证 recipe、Claim、round-trip、冲突处理和重复执行收敛。

### 完成证据

- 可静态枚举的完整输入域已审查全部命中与未命中形态，没有未解释的漏收或误收；无法枚举的部分、明确排除项和验证入口均有证据。
- 语义分组、自然顺序和写回身份符合实际消费者。
- round-trip 保持未授权内容，Claim 不冲突，重复执行收敛。

### 返回位置

运行时消费者判断错误时返回流程 1。漏收、误收、错组或 recipe 错误留在本流程。只有真实样本证明 Builtin、Rules 或 Placeholder 无法表达关系时，进入可信 Lua 子流程。

## 流程 3：翻译资源准备

### 进入条件

处理已经具备可靠提取资产、但需要准备或修正术语、Placeholder、Prompt、Profile、供应商配置或语言选择的情况。

### 必读文档

- 读[术语规格](../../docs/rpg-maker/terminology.md)、[Prompt 规格](../../docs/rpg-maker/prompts.md)和[配置规格](../../docs/runtime/configuration.md)。
- 使用自定义 Placeholder 时再读[Rules 规格](../../docs/rpg-maker/rules.md)。
- 判断资源如何影响译文状态时再读[Translate 规格](../../docs/rpg-maker/translation.md)。

### 任务清单

- 从真实语料建立稳定术语，只保护确有协议意义的 Placeholder。
- 从实际消费者确认自定义 Placeholder 的协议范围，并检查已确认范围内全部未保护和误保护跨度。
- 让 Prompt 与现行模型输入输出契约保持一致。
- 只把供应商、部署环境或使用者真正可选的策略写入配置。
- 当实际翻译结果表明现有工件阻碍收敛时，酌情修改相关规则文件、`config.toml` 或 Prompt，以更快完成重试、提高译文质量并让问题更容易定位；不要为了沿用初始工件而重复无效请求。
- 在首次模型请求前完成相关工件的格式和内容验证。

### 完成证据

- 每项资源都有真实语料、协议约束或外部选择作为依据。
- 可静态枚举的 Placeholder 协议没有未解释的未保护或误保护跨度；无法枚举的部分和验证入口明确。
- 工件通过其责任文档规定的验证。
- Prompt、Profile 和供应商配置边界清楚；实际选中 Client 的 API key 值未写入受版本控制材料。

### 返回位置

协议壳来自错误提取边界时返回流程 2。术语无法可靠消歧时缩窄或删除条目。网络或供应商运行故障进入流程 6。

## 流程 4：翻译与质量审核

### 进入条件

处理存在待翻译、非 Current 或 unresolved 单元，或者需要审核既有译文质量的情况。

### 必读文档

- 先读[Translate 规格](../../docs/rpg-maker/translation.md)。
- 根据具体问题再读[术语规格](../../docs/rpg-maker/terminology.md)、[Prompt 规格](../../docs/rpg-maker/prompts.md)或[Rules 规格中的 Placeholder 契约](../../docs/rpg-maker/rules.md)。
- 网络与模型响应外层故障再读[Chat Completions 运行时规格](../../docs/runtime/chat-completions.md)。
- 调查 Standard 最终输入输出、重试、验收、提交终态或记录健康状态时再读[任务记录规格](../../docs/rpg-maker/task-records.md)；调查运行级摘要时再读[项目日志规格](../../docs/runtime/project-log.md)。

### 任务清单

- 确认本轮显式提供或复用的翻译资源及其当前性。
- 执行一轮 Translate，保留已经合法提交的部分进度；记录本轮前后的剩余位置与去重族、拒绝和不可用原因、任务结果以及代表性质量问题。
- 根据本轮真实结果选择下一步：仍可直接续作时再次执行 Translate；同类问题可由工件修复时修改相关规则文件；调整模型任务、Profile、Client、语言或诊断呈现更有效时，酌情修改 `config.toml` 或 Prompt。不要把配置和 Prompt 留给使用者手工试错。
- 修改后先按责任文档验证工件，再从最早受影响阶段重跑：影响提取身份、分组或写回位置时返回 Extract；只影响 Standard 翻译语义时重新 Translate。规则、Profile、Client 或 Prompt 改变引起的 Stale 属于待重新验收的当前语义，不得误判为状态损坏。
- 重复“执行—分析—直接续作或修改工件—重跑”，用剩余位置与族的净减少、拒绝原因变化和同类问题是否仍能批量修复判断能否显著推进；不设置固定重试轮数、固定剩余数量或人工补译门槛。
- 只有证据表明继续 Translate 或调整规则文件、`config.toml`、Prompt 已不能显著推进，并且剩余数量和复杂度已适合人工收尾时，才进入可信 Lua 子流程。使用
  独立项目 `lua` 命令的 `ctx.standard` 验收与提交；按完整身份、原文、形状和去重族影响
  审核候选，不用直接 SQL 写受管表，也不用 Translate Lua 标量 state 冒充 Standard state。
- 调查自定义资源是否生效时，先在对应 Standard 任务记录中核对最终 System/User、Thinking、Assistant、重试、验收和提交终态；普通 JSONL 只核对运行摘要，必要时再用项目数据库复核权威状态。
- 同时检查 `Complete`、`Partial`、`Unavailable`，以及任务状态、unit state 和代表性译文。
- 区分机器协议验收、状态传播和语言质量，只修正真正拥有问题的资源或阶段。

### 完成证据

- 约定范围内的译文状态与实际产出一致。
- 代表性译文通过术语、协议壳、自然语言和上下文审核。
- 若进入人工补译，已有逐轮证据证明自动路径不能再显著推进，且剩余人工工作量与复杂度可接受。
- 剩余位置、原因及准确续作入口明确；退出码不被单独当作完成证据。

### 返回位置

漏收、错组或规则修改影响提取语义时返回流程 2。规则文件、配置、Prompt、Placeholder 或语言质量问题返回流程 3 后再进入本流程。仍能显著推进的正常 `Partial` 留在本流程继续收敛；只有达到人工收尾条件时才进入可信 Lua 子流程。技术错误进入流程 6。

## 流程 5：写回与隔离试玩

### 进入条件

处理已有可接受译文，需要生成候选内容树、检查写回差异或在游戏内验证的情况。

### 必读文档

- 先读[WriteBack 规格](../../docs/rpg-maker/write-back.md)。
- 发布失败或终态不明时再读[目录发布规格](../../docs/runtime/directory-publishing.md)。
- 启用可信 Lua 时同时读取可信 Lua 子流程列出的文档。

### 任务清单

- 从冻结来源生成新候选，不把原游戏或旧候选当作新权威来源。
- 检查变化只发生在已确认的 Claim 位置，未知字段和协议壳保持不变。
- 把候选内容树部署到隔离游戏副本。
- 试玩对话、选择、插件路径、协议壳和代表性布局，并追踪未翻译内容的来源。

### 完成证据

- 候选确定生成，原游戏保持不变。
- 写回差异符合 Claim、recipe 和协议边界。
- 代表性场景通过；人工布局项、保留原文项和剩余缺口明确。
- 候选内容树没有被误称为完整游戏包。

### 返回位置

漏文、误收、错组或 recipe 错误返回流程 2。译文质量问题返回流程 3 或流程 4。宽度或冻结来源事实错误返回流程 1。发布终态未知时进入流程 6，禁止自动重试副作用。

## 流程 6：诊断、恢复与安全续作

### 进入条件

处理技术失败、取消、`Partial`、`Unavailable`、项目无效、锁、SQLite、HTTP、发布问题、日志警告、状态矛盾或结果终态不明。

### 必读文档

- 先读[命令行规格](../../docs/runtime/cli.md)、[项目日志规格](../../docs/runtime/project-log.md)和失败阶段的现行规格。
- Standard 任务失败、部分完成或取消时再读[任务记录规格](../../docs/rpg-maker/task-records.md)；按实际原因再读[SQLite 运行时规格](../../docs/runtime/sqlite.md)、[目录发布规格](../../docs/runtime/directory-publishing.md)、[Chat Completions 运行时规格](../../docs/runtime/chat-completions.md)或可信 Lua 文档。

### 任务清单

- 区分正常部分结果、暂时不可用、技术错误和内部不变量破坏。
- 收集命令终态、运行标识、运行级 JSONL 摘要、项目状态和相关底层原因；Standard 调查优先读取对应单任务记录。
- 分别确认事务、候选发布和保存运行方案的终态。
- 定位唯一责任阶段，复用已经合法提交的进度并确定恢复入口。

### 完成证据

- 具体原因、状态影响、权威来源和副作用终态明确。
- 恢复位置由现行契约支持。
- 获得授权并执行恢复时，相关不变量和目标阶段得到重新验证。

### 返回位置

正常部分结果返回流程 4 续作。来源、提取、资源或写回问题返回各自责任流程。发布终态未知时保留现场并暂停副作用；不得自动重试。数据库高级修复必须遵守本 Skill 的可恢复副本、事务和不变量复核边界。

## 条件子流程：可信 Lua

### 进入条件

满足以下任一条件时进入：

- 真实样本证明 Builtin、Rules 或 Placeholder 无法表达动态枚举、跨节点关系、多目标同步、
  私有状态或恢复协议；
- 流程 4 的逐轮证据表明自动路径已不能显著推进，剩余工作适合人工收尾，并且已有人工作品需要按 Standard 的完整 Lines、上下文、Placeholder、去重和 Current 语义验收并提交到现存 Standard 单元。

### 必读文档

- 读[Lua 技术参考](../../docs/rpg-maker/lua.md)、[Lua Cookbook](../../docs/rpg-maker/lua-cookbook.md)和对应阶段规格。

### 任务清单

- 先区分阶段扩展与一次性项目程序：现存 Standard 单元的人工补译使用独立 `lua` 和
  `ctx.standard`；只有扩展自己拥有身份、状态或写回协议时才进入 Extract/Translate/
  WriteBack 阶段 Lua。
- 进入人工补译前复核流程 4 的停止证据；若直接续作或修改规则文件、`config.toml`、Prompt 仍可批量推进，返回流程 4，不把可自动收敛的工作提前转成人工逐项处理。
- 人工补译脚本按完整只读身份定位唯一单元，复核 original、content kind、line policy、
  status 与 family size；候选按 model text 中的 ATT token 编写，只有确需替换 Current 时
  才显式设置 `replace_current=true`。
- 设计最小脚本边界、稳定身份、事务、私有状态和幂等交接；Standard 人工提交的 state 和
  事务由核心拥有，不在 Lua 中读取、构造或复制。
- 复用 Standard 能力，不在 Lua 中重建已有机制，也不直接修改 ATT 受管翻译表。
- 调查 Translate Lua 时读取脚本语义、普通 JSONL 和项目数据库；Lua 不生成 Standard 任务记录，不从一次 `ctx.llm` 响应猜测脚本验收或提交终态。
- 独立项目 Lua 不生成 LLM TaskBlock；以每次 `standard:accept` 的结构化结果和项目数据库
  作为权威提交证据。
- 验证重复运行、正常拒绝、同族冲突、Current 覆盖、失败、取消、候选丢弃和恢复行为。

### 完成证据

- 只有必要阶段启用阶段 Lua；一次性项目脚本未被保存进任何运行方案。
- 私有状态、事务边界和副作用责任明确。
- Standard 人工提交的 translation/state 配对、传播位置和相同 Profile 的 Current 结果
  一致；重复执行收敛，失败不会伪造成功或污染发布语义。

### 返回位置

静态确定路径足够时返回 Rules；只需保护协议跨度时返回 Placeholder；只涉及用词时返回
术语或 Prompt；人工候选验收完成后返回流程 4；Lua 运行失败进入流程 6。

## 固定回退原则

- 漏收、误收、错组或 recipe 错误返回流程 2。
- 规则文件、`config.toml`、Prompt、Placeholder 或语言质量问题返回流程 2 或流程 3；从最早受影响阶段重跑后进入流程 4 持续收敛。
- 只在自动路径不能再显著推进且剩余工作适合人工收尾时进入 Standard 人工补译。
- 宽度、引擎、游戏根或冻结来源事实错误返回流程 1。
- 发布终态未知进入流程 6，禁止自动重试副作用。
