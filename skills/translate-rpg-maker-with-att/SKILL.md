# 用 ATT 完成 RPG Maker 翻译

## 先判断请求模式

先按用户允许的动作选择模式：

- **只读模式**：分析、解释、审查、诊断、状态核对或只给建议。只读项目、现有任务清单和
  文档；不创建或修改任务清单，不运行会改变 ATT 项目、发出模型请求或发布输出的命令。
- **执行模式**：用户要求执行、继续、修复、提交人工译文、写回或交付。任务负责人必须
  创建或恢复唯一任务清单，再进行项目修改、模型请求或发布。
- **协作者**：只完成任务负责人委派的具体 TODO。不得修改任务清单，也不得扩大写入、
  外部请求或费用范围。

用户把只读请求改为执行请求后，才进入执行模式。不要把“检查一下”“分析原因”解释成
修改授权。

## 绑定本次实际 ATT

解释或执行 ATT 行为前，先确定本次实际使用的 `att.exe` 绝对路径；它的父目录是本次唯一
发布目录。先读取发布根 `README.md`、`docs/README.md`，再按
[工作要求](references/workflow.md#产品能力与文档路由)读取本次事实需要的现行文档。
命令、参数、配置、API、状态、错误、事务和恢复行为只以这些文档及实际程序为准。

不得转而使用源码仓库、Git 历史、`target/`、其他 ATT 安装、旧对话或记忆补足缺失的产品
事实。发布目录缺少程序、根说明、所需文档或资源时，停止依赖该事实的执行并明确报告。

发布目录中的 `config.toml` 只是可编辑的起始配置，不是默认运行配置。除 Help 和 Version
外，执行前必须确定本次显式 `--config`：

- 只接受用户明确指定、已经核实的任务清单记录，或可验证的实际调用事实；
- 记录调用 cwd、配置绝对路径和 SHA-256；按现行配置文档只解析并记录本次命令实际消费
  的根，项目命令通常需要 `projects.root`，Translate 才需要 `prompts.root`；
- 没有可靠配置选择时停止执行，不按位置、文件名或日期猜测；
- 配置副本换目录会改变内部相对路径的含义，不能把备份路径直接用于命令。

任务清单记录实际程序路径、`--version` 输出、程序 SHA-256、发布目录、配置和项目身份。
只读请求只记录在审查报告中，不为此新建清单。

## 按请求深度调查

先判断本次属于哪一种只读或执行请求：

- 通用解释只读取实际发布中直接说明该概念、命令或状态的文档，不要求项目、配置或任务
  清单事实；
- 项目特定的只读诊断只核对回答该问题必需的项目事实，不新建清单、不执行修改；
- 执行请求才完整读取 [工作要求](references/workflow.md)，并在修改前核对：

- 用户目标、范围、必须保持的行为和停止位置；
- 原游戏、实际加载位置、engine、项目名和 ATT 项目工作区；
- 当前来源、配置、运行方案、提取结果、译文、输出和异常状态；
- 玩家可见文本的真实消费者，以及提取、翻译、写回如何定位同一内容；
- 已有授权、仍需用户决定的选择、费用和不可恢复风险。

执行模式以以下内容共同识别任务，不能只看文件名：engine、项目名、绝对项目工作区、
实际 `projects.root`、游戏来源版本、用户目标、范围和预期输出。

从整个执行任务形成提取、翻译、写回的路线和验证方法。任务清单固定只有三个阶段：

1. 提取
2. 翻译
3. 写回

ATT 的 Init 是产品命令；需要时作为提取阶段中建立或核对项目、冻结来源的 TODO，不增加
第四阶段。人工审校、Current 译文修订和独立 Lua 候选属于翻译阶段。

## 新建、继续或返修任务清单

只在执行模式使用任务清单：

1. 用户给出清单路径时，完整读取并核对内部任务身份和实际项目状态。
2. 用户未给出路径时，只在用户认可的外部任务根中查找全部
   `ATT-翻译任务-*.md`，不扫描原游戏、ATT 发布目录、`projects.root`、项目工作区或整块
   磁盘。
3. 没有匹配清单时，完整读取
   [任务产物规范](references/task-artifacts.md)和
   [任务清单模板](assets/task-list-template.md)，由任务负责人亲自创建
   `ATT-翻译任务-<engine>-<safe-project>-<YYYYMMDD>[-NN].md`。
4. 同一目标的未完成任务继续原清单；同一交付结果失效或需要返修时恢复原清单，保留旧
   TODO 和交付记录并追加复核 TODO。
5. 新游戏版本、新范围、新输出或独立目标使用新清单，并引用相关旧清单。
6. 多份清单同时匹配时停止选择，报告各自身份差异；不按日期猜测、不自动合并。

任务根必须位于原游戏、实际加载目录、ATT 发布目录、整个 `projects.root`、任何 ATT 项目
工作区、`write_back`、最终交付目录、系统临时目录和 Skill 安装目录之外。没有安全且能
持续保存的位置时，先请用户指定。

同一任务只维护一个清单，完成后原地保留。任务负责人是唯一写入者。

## 编写和更新 TODO

只展开当前阶段的真实 TODO；后续阶段先保留简短等待说明，进入后再依据最新事实展开。
根据风险、授权、恢复点和证据决定是否拆分，不为目录整齐预建工作。

每个 TODO 使用阶段前缀和任务内唯一编号，例如 `EX-01`、`TR-03`、`WB-02`。编号一经写入
不重排、不复用。开始前写明可观察的完成标准：

```markdown
- [ ] TR-03 审校菜单与帮助文本
  - 完成标准：<能够观察和检查的结果>
```

完成后立即记录结果和证据：

```markdown
- [x] TR-03 审校菜单与帮助文本
  - 完成标准：<原有标准>
  - 结果：<简短结论>
  - 证据：<绝对路径、ATT RunId、查询或运行结果；说明它证明什么>
```

部分完成或阻塞时保持未勾选，并补充：

```markdown
  - 已确认进展：<已经成立的事实>
  - 证据：<已经成立的部分由什么证明>
  - 待确认：<缺少的事实、决定或授权>
```

执行项目修改、外部请求或发布前，清单必须已有对应 TODO。开始、完成、部分完成或阻塞时
立即更新，不在结束后凭记忆补写。

- 当前阶段、活动 TODO、下一步、最后权威状态和阻塞只写在“当前状态”。
- 命令退出码、目录存在、日志存在或口头声明不能单独证明完成。
- 已完成 TODO、已引用产物和历史交付记录不得覆盖或改写；旧结论失效时追加复核 TODO。
- 只有目标、范围、输入、授权、配置或已验收结果实质变化时才记录重要决定。
- 人工输入、备份、证据、QA 和临时材料的路径、名称、保留与协作者写入遵循
  [任务产物规范](references/task-artifacts.md)。

## 执行、授权和协作

按 [工作要求](references/workflow.md)选择能力、读取文档、执行当前阶段并处理结果。不要
在 Skill 中推断未记录的 CLI 或 API。

用户授权执行翻译、修复或交付时，可以修改任务范围内、可恢复且不改变用户产品选择的
Rules、Placeholder、Terminology、Prompt、项目 Lua 和相关项目设置。修改前先查清责任、
全部实际使用位置和后续影响，保存必要的修改前证据，并在完整受影响内容上比较修改前后
结果。

普通调查和人工补译不得直接 SQL 修改 ATT 受管表。只有用户明确授权“高级数据库修复”，
并且实际发布文档确认该路径和要求时，才按现行文档执行；它不是普通译文提交方式。

Lua 是可信程序，不是 sandbox。本次运行方案或项目状态会使用 Lua，或请求明确涉及 Lua
时，按
[Lua 外部依赖与副作用](references/workflow.md#lua-外部依赖与副作用)读取实际产品契约，
核对主程序、模块解析环境、可能或已经实际加载和执行的外部依赖，以及受管 API 外的文件、
进程、网络和 SQLite 副作用。不得假定依赖位于项目内、进入阶段快照或受到 ATT 事务管理；
未获相应授权时停止。成功提交后脚本再失败，不得假定此前副作用已经回滚。

不得自行改变凭据、模型、供应商、费用选择、源语言、目标语言、外部服务、用户范围或唯一
原件。缺少这些决定时停止并说明。

委派时，任务负责人应给出 TODO、只读或写入范围、唯一输出路径、是否允许运行 ATT 或发出
模型请求、预期证据和停止条件。不同协作者不得写同一人工产物；同一 ATT 项目的写命令和
可能收费的 Translate 请求由任务负责人统一安排，不得重复执行。

## 中断和异常

继续或接手任务时，先读取清单，再核对实际发布、配置、项目权威状态和引用证据。日志与
`task-records` 只用于诊断，不替代数据库、冻结来源或发布终态。

本次运行方案或项目状态使用 Lua 时，还要重新核对当前模块解析环境、外部依赖的内容与
可用性，以及前次运行可能留下的非受管副作用；不能只凭主程序快照或旧依赖哈希继续。

出现以下情况立即停止依赖该事实的后续工作，更新清单并报告：

- 产品文档、必要资源、配置选择或用户决定缺失；
- 输入、数据库提交、运行方案或发布终态无法确认；
- 配置影响尚未查清，或修改后完整检查失败；
- 连续执行没有有效进展；
- 继续会扩大范围、增加费用、触发未授权副作用或造成不可恢复改变。

Partial、Unavailable、Manual、取消、已生效但运行方案未保存、OutcomeUnknown、日志故障和
候选发布异常分别按
[工作要求的结果与恢复规则](references/workflow.md#结果解释与恢复)处理。状态不明时保留
现场、重新读取实际文档并观测权威状态，不盲目重跑。

## 完成和交付

只有以下条件全部满足，才能追加一条完成的交付记录：

- 本次范围内所有 TODO 已完成，且涉及阶段满足工作要求中的完成条件；
- 完整游戏翻译有提取、翻译和写回的当前证据；
- 范围内没有未解释的玩家可见文本遗漏、未翻译内容、拒绝、质量问题或写回差异；
- 项目配置修改已完成全部影响检查和修改后验证；
- 任务使用 Lua 时，实际解析环境、动态依赖和非受管副作用已经核对，并与本轮授权和证据
  一致；
- 权威项目状态、实际输出和用户要求的加载位置已经核对；
- 交付记录写明输出、验证、未验证内容和剩余风险。

返修完成时追加新的日期性交付记录，不覆盖旧记录。只读模式不修改清单，只交付审查结论、
证据、未确认内容和如果执行修复所需的授权。
