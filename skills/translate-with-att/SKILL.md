# 使用 ATT 完成翻译

## 先确定工作模式

按用户实际授权选择：

- **只读**：解释、审查、诊断或状态核对。只读取产品文档、项目和已有任务材料，不运行会
  修改项目、发出模型请求或发布输出的命令。
- **执行**：用户要求建立、继续、翻译、修复、写回或交付。先建立或恢复唯一任务清单，
  再执行已授权操作。
- **协作者**：只完成负责人分配的 TODO 和文件范围，不创建第二份清单，不重复模型请求。

不要把“检查”“分析”解释成修改授权。

## 绑定实际 ATT 和权威文档

1. 确定本次实际使用的 `att.exe` 绝对路径、版本和 SHA-256。
2. 把它的发布目录作为产品知识根，读取其中 `README.md` 与 `docs/README.md`。
3. 按文档总入口读取本次引擎、阶段、格式和运行能力的现行规格。
4. 确定显式配置、调用 cwd、解析后的项目根和 Prompt 根。

命令、参数、JSONL、配置、状态、错误、数据库、Lua 和恢复行为只以该发布目录的文档与
实际程序为准。不要用其他安装、源码仓库、Git 历史、旧对话或记忆补足缺失事实。发布内容
不完整时，停止依赖缺失事实的执行并明确报告。

## 选择项目

先调查游戏运行时真正读取的内容，再决定：

- RPG Maker MV/MZ 原生数据和 Rules 能完整表达的内容，使用对应 `mv` 或 `mz` 项目；
- 外部操作者或工具能提供 ATT JSONL 的任意内容，使用 `generic` 项目；
- 一个游戏同时存在两类内容时，建立彼此独立的 MV/MZ 与 Generic 项目。

组合使用时，记录每类内容的唯一项目所有者、外部 JSONL 转换方式和最终消费方式。项目的
数据库、术语、Placeholder、状态、日志、模型任务记录和输出互不共享，不要让两个项目
重复拥有同一文本。公共配置可以定义相同的 Profile，但每个项目独立保存自己的选择。

Generic JSONL 如何产生和如何回写由外部操作者负责。修改 JSONL 后，先按 Generic 文档
重新 Extract，再 Translate 或 WriteBack。

保留全局去重。少量相同原文需要不同译文时，先完成自动翻译，再按 Lua 文档精确修订目标
Unit；不要为少量例外重写提取或去重规则。

## 管理执行任务

执行型任务完整读取发布目录中的：

- `docs/guides/translation-project.md`
- `docs/guides/task-artifacts.md`
- `docs/guides/task-list-template.md`

用户给出清单时先完整读取并核对身份。没有清单时，只在安全任务根查找当前目标的清单；
没有匹配项才复制模板建立一份。多份同时匹配时停止选择，不按日期猜测。

清单只保留提取、翻译、写回三个阶段。Init 是提取阶段的前置工作。一个游戏使用多个 ATT
项目时，在同一清单中分别记录各项目，不为每个项目制造彼此冲突的总清单。

每个 TODO 在执行前写明可观察的完成标准，完成后立即补充结果和证据。只展开当前阶段；
新事实使旧结论失效时追加复核 TODO，不改写历史完成记录。

## 执行与判断结果

- 在修改项目、发出模型请求或发布输出前确认相应授权。
- 不自行改变模型、凭据、费用、语言、范围、外部服务或唯一原件。
- 按项目文档执行 Init、Extract、Translate 和 WriteBack，不从 Skill 猜测参数。
- 修改 Rules、术语、Placeholder、Prompt 或 Lua 前确认全部实际使用位置和影响。
- Lua 是项目数据库原子事务；记录脚本、参数和 SHA-256，不把它当游戏文件扩展机制。
- 使用数据库和发布终态判断结果；日志和任务记录只用于诊断。
- 分别解释 Complete、Partial、Unavailable、取消与 outcome unknown，不把退出码零等同于
  整个翻译已经完成。
- 状态不明时停止重复请求和写入，保留现场，按对应文档重新观察权威状态。

## 验收与交付

只有以下事实都成立才宣布完成：

- 范围内文本的来源、项目所有者和写回关系有当前证据；
- 没有未解释的遗漏、未译内容、拒绝或质量问题；
- 术语、Placeholder、控制符、人称、语气和实际运行效果已经按范围审查；
- 每个项目的数据库和 WriteBack 都对应当前输入；
- Generic 输出已经由负责的外部过程消费并验证；
- 交付记录写明输出、验证、未验证内容和剩余风险。

只读任务不修改清单，只交付结论、证据、未确认事实和执行修复所需授权。
