# Kirikiri / KAG / TJS 显示消费者与补丁加载经验

适用于 Kirikiri 系游戏通过外部适配器将 KAG 场景（`.ks`）、TJS 脚本（`.tjs`）或自定义文本窗口接入 ATT Generic 的任务。

## 1. 来源映射与语法解析

- **区分脚本区与正文区**：同一游戏常混用 KAG 正文、自定义宏属性和 TJS 界面脚本。使用匹配方言的词法/语法解析器识别命令、嵌套引号（如外层 KAG 引号套内层 TJS 字符串）、转义和注释，不对整行做盲目正则替换。
- **保持完整语境**：按 [Generic JSONL 规格](../../../docs/generic/jsonl.md) 将同一场景的连续对白、提示和相关选项放在同一 Group；在外部映射中保存文件、结构位置、稳定 ID 与写回偏移。接入批量翻译前先验证未修改文本的往返一致。

## 2. 区分显示文字与内部身份

同一字符串可能既用于画面绘制，又作为对象名、字典键、按钮查找键、历史记录身份或存档键：

- 保持内部键、`label`、`storage`、`target`、条件表达式和事件绑定为原值；即使属性名为 `text`，也需确认其是否参与逻辑查找。
- 当某个值同时用于逻辑查找和界面显示时，保留内部身份不变，在最终显示调用边界建立“原身份 → 译文”映射。

## 3. 资源加载优先级与原生窗口

修改文件后若画面未生效，追踪启动脚本、归档挂载和实际加载路径：

- **归档限定路径**：Kirikiri 支持按 basename 查找，也支持 `archive.xp3>member.ks` 形式的归档限定加载。若调用方显式指定了归档名，外部松散文件或普通 `patch.xp3` 中的同名文件可能无法覆盖它，需在调用处或对应归档内修改。
- **多重标题与原生菜单**：窗口标题、`Config.tjs`、主菜单标题和顶部原生菜单（caption / hint）可能各自独立赋值；字体选择等原生对话框也可能绕过游戏 Layer 绘字直接调用系统接口，需分别定位实际 setter 或构造参数。
- **缓存与存档状态**：验证修改时需完全重启游戏并进入新事件，避免把内存缓存或旧存档保存的文本误判为补丁未生效。

## 4. 自定义窗口、动态文本与特殊符号

- **控制码与转义**：确认文本窗口对颜色、换行、等待和格式化占位符的解析规则，通过 [Placeholder](../../../docs/translation/placeholders.md) 或外部结构保护控制符。
- **KAG 左方括号转义**：在标准 KAG 正文中，裸 `[` 会触发标签解析（参见 [KAGParser](https://github.com/krkrz/krkr2/blob/master/kirikiri2/branches/2.32stable/kirikiri2/src/core/utils/KAGParser.cpp)）。若译文正文中新增了可见的 ASCII 左方括号，需按目标方言转义为 `[[`，同时保留原有的指令标签不变。
- **动态表达式**：对字符串拼接或格式化模板，保留变量、运算符和求值顺序，仅提取已确认的可见字面量或模板文本槽。
- **TJS 字典空键边界**：在 TJS 字典查表映射时注意检查非空字符串；部分构建中对字典传入空字符串 `""` 会使底层 `PropGet` 退化为读取对象自身属性而引发类型错误（参见 [TJS2 接口说明](https://krkrz.github.io/docs/tjs2/j/contents/interface.html)）。

## 5. 文本测量与补丁封包

- **宽度测量同步**：若居中文本、按钮宽度或自动换行在汉化后偏移，检查代码是否仍按原文长度计算尺寸，确保测量与绘制使用同一份最终显示译文。
- **XP3 封包与部署**：按目标构建支持的归档格式打包补丁，排除无关游戏本体资产、存档、ATT 数据库与日志；封包后重新解包校验文件列表、编码、BOM 及脚本结构。
