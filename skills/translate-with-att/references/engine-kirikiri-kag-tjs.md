# Kirikiri / KAG / TJS 显示消费者与补丁加载经验

## 适用结构与证据边界

适用于 Kirikiri 系游戏通过外部适配器把 KAG 场景、TJS 界面或自定义文本窗口接入 ATT Generic
的任务。遇到正文已翻译但标题、菜单、提示仍为原文，或汉化后出现对象重名、混排与脚本错误时，
先按本页追溯实际显示消费者，不直接重新翻译全部字符串。

真实材料支持以下处理方法：区分显示文字与内部身份；追踪归档限定加载和 basename 加载；
保留场景指令与自定义窗口控制符；根据实际显示译文计算布局；对 XP3 补丁做重新解包和结构对账。
部分旧候选取得过菜单与提示框的运行证据，后续修改只有静态验证；旧场景的运行结果不能证明
后续候选已经运行正常。这些经验不表示 ATT 提供 Kirikiri 原生提取器、TJS 编译器或通用 XP3 writer，
也不表示所有 Kirikiri 分支、加密归档与窗口实现具有相同规则。

## 1. 先建立可执行的来源映射

- 确认实际引擎构建、活动归档、补丁加载入口、启动场景、文本编码及外部工具的支持范围。
  `.ks`、`.tjs` 等扩展名只是线索；同一游戏可以同时使用 KAG 正文、自定义命令、TJS 窗口
  和图片文字，不能把找到的所有非 ASCII 字符串都当作可翻译正文。
- 为每个显示类别记录来源文件、结构位置、实际调用方和写回所有者。场景正文、静态标签属性、
  动态表达式字面量、原生菜单 caption、提示 hint、窗口标题分别调查；其中一类完成不能证明
  其他类已经提取。图片上的文字单独标记，不把未处理的图片字算作非图片文本完成。
- 用目标方言的 parser 或已经验证的限定转换识别命令、引号、转义、注释、脚本区与正文区。
  表达式属性可能具有外层 KAG 引号和内层 TJS 引号，不能靠扁平的引号正则替换整行。
  排除注释与已证明不可执行的说明段；缺少控制流证据的分支保留待确认状态。
- 接入前完成原文往返：相同源资源经读取、映射、回填后，内部键、跳转、表达式和非文本数据
  不变。回填前核对当前输入，源结构已变化时重新定位，不向新版文件套用旧偏移。

外部映射保存来源、稳定身份、自然顺序和写回位置；模型输入只使用
[Generic JSONL 的公开字段](../../../docs/generic/jsonl.md)。同一提示、相关选项或同一场景中共同
决定含义的文本保持完整语境，不为了控制码拆分而把相关叶子变成无上下文的独立任务。
容器、方言、解密与资源重建由引擎适配器承担；ATT 管理术语、模型、译文状态和验收。

## 2. 对象重名或选择逻辑异常时，先查内部身份

同一字符串可能既被绘制，又作为对象名称、字典键、按钮查找键、记录键或资源引用使用。
汉化后出现重名错误时，先追踪该字符串的赋值和读取者，比较原版与候选的内部身份及引用，
不要仅修改当前错误提示中的重复值。

- 内部键、地图与逻辑表、资源名、label、storage、target、条件和事件绑定保持原值。
  给字段名叫 `text` 的位置分类时，同样检查消费者；删除按钮或查找对象的参数可能是身份。
- 显示与查找共用一值时，在有证据的显示边界建立“原身份 → 显示文字”对应；不要修改公共
  名称恢复函数、字典读取函数或所有字符串访问，使显示变更传播到逻辑消费者。
- 菜单选中后的动作参数、条件与跳转保持原样。验证不只比较赋值语句，还要确认传入该语句的值
  没有提前变成译文，尤其是名称被用于查找、历史记录或存档身份的路径。
- 复用旧汉化前确认它对应当前来源、结构位置及显示语境。完整原文精确匹配与结构对应可作为
  复用证据；同字面但语境不同的来源不能直接合并。旧版的逻辑表和对象身份不整体覆盖新版。

## 3. 文件已改但画面未变时，追踪最终加载与赋值

- 从启动脚本、归档登记和实际加载调用追踪资源查找顺序。修改文件放在 `script/` 或 `system/`
  下，不保证按 basename 请求的消费者会读到它；只有确认实际路径后才增加必要的覆盖入口。
  需要多个入口时，检查对应内容一致、大小写与同名冲突，不能用无差别复制制造更多来源。
- 调用显式指定 `archive.xp3>member.ks` 一类归档限定位置时，不假定普通补丁中的同名成员会
  覆盖它。按目标加载器确认这类引用，再决定在实际执行的消费者修改显示参数，或调整已确认
  的加载入口；保留与本次显示无关的原版元数据和流程。
- 窗口标题、主菜单标题和关于信息可能使用不同字段，也可能在后续被重新赋值。追踪最终执行
  的标题命令或 caption setter，不因某个同字面变量已有译文就认为标题已生效。
- 顶部原生菜单与游戏内菜单分开定位。菜单构造脚本、音量分类脚本和场景选项可能分别加载；
  核对各自 caption、hint 和覆盖路径，保留快捷键、通道标识、回调与条件。

归档优先级、路径限定语法和缓存行为属于目标构建；未确认的规则记为待验证，不能从一个补丁
文件名推导整个引擎系列的加载顺序。

## 4. 自定义窗口与动态文本要保留解释层

- 查看真实文本窗口的 write、逐字处理和 draw 调用，确定颜色、换行、等待、转义以及格式化
  占位符的解释方式。有的实现使用普通 ASCII 字符作为控制码；控制字母表从当前解析器取得，
  不把某个窗口的规则推广到 KAG 全文或其他 TJS 字符串。
- 控制符留在外部结构中，或使用符合 ATT 契约的 Placeholder；回填后核对类型、顺序、数量
  以及转义关系。Generic 允许正文 LF 数量变化，游戏写回是否允许变化由实际消费者决定，
  不把游戏局部限制描述成 ATT 的通用拒绝规则。
- 完整句子在进入逐字绘制前翻译一次。后续字形绘制使用已经确认的目标文字，避免单字查表
  再次改写译文；全局任意子串替换可能造成中文与原文混排，应回到完整显示边界修复。
- 动态拼接不是“无法翻译”的排除理由。把表达式中的可见字面量、格式化模板和运行时名称
  分别绑定来源：变量、操作符、对象索引和身份比较保留；只修改已确认的显示值或其专用映射。
  回填前同时检查外层 KAG 属性和内层 TJS 表达式，原字面量的转义不能被 JSON 再编码破坏。
- 模型可能在正文中新增 ASCII 方括号；直接写入场景会被 KAG 当作指令解析。仅对确认新增的
  文字括号选择目标方言支持的转义或显示等价形式，保留原有指令不动；不能全局替换所有括号。
- 对译文做结构与控制码校验；是否允许保留特定文字另按语境与任务要求判断。假名检测区间
  可能包含中点等标点，命中区间只能生成候选，不能仅凭标点命中判定漏译或退回有效译文。

显示映射保留完整来源与语境身份，动态值或未命中值采用明确的回退行为并计入遗漏报告。
不能把大量精确对应或某个提示框显示正确当作动态界面全覆盖的证据。

## 5. 译文显示正常但布局偏移时，检查测量对象

绘制文字已变成译文，而居中、按钮宽度或换行仍按原文长度计算，会产生位置偏移或裁切。
测量与绘制应使用同一实际显示字符串，并保留内部名称和动作参数。若字体或渲染 API 提供
实际宽度，按当前窗口的测量机制处理；不能把字符数居中修复推广为所有字体都已排版正确。

字体名称存在和静态字符覆盖不等于引擎实际选择了该字体。字体、缺字、逐字显示、行高、描边、
换行和按钮边界仍分别取得证据，图片菜单的文字不受普通字体补丁影响。

## 6. 写回、补丁交付与验收

[Generic WriteBack](../../../docs/generic/write-back.md)生成译后 JSONL；外部反向转换、资源重建
及部署完成后，游戏才可能采用它。分别报告 ATT 的接受、拒绝、剩余与写回状态，以及最终游戏
消费者的覆盖，不把退出码或 Extract 数量当成完整汉化证明。

1. 在处理副本部署最小必要的脚本、显示对应、字体或资源修改；续跑保留已有进度。建立补丁
   清单，排除无关原游戏资产、存档、项目数据库、日志、模型记录、配置与密钥等非交付内容。
2. 按目标归档格式和工具的支持范围封包，再用独立读取路径重新解包。核对成员路径、编码与 BOM、
   长度、分段边界、适用的校验字段和预期内容；不把明文 XP3 往返成功当作加密或其他分支也支持。
3. 比较非目标逻辑表、地图、内部键、引用、脚本骨架和场景控制序列；别名与归档限定加载单独
   对账。代码比较同时考虑赋值的数据流，不能只删除所有字符串后比较骨架。
4. 从实际补丁清单核对最终安装文件，确认不存在更新补丁的旧优先级覆盖。要验证独立安装，
   在干净原版副本按真实安装方式应用最终补丁；工作副本正常不足以证明补丁包含全部依赖。
5. 运行验证依任务授权进行，覆盖实际执行文件与工作目录、标题、原生菜单、问答、动态提示、
   逐字正文、历史记录和必要的玩法路径。用户明确要求不启动时只做静态检查，列出未验证场景，
   不启动游戏，也不把旧候选的运行结果写成当前补丁的证明。

上述经验用于选择调查和验证动作，不增加 ATT 原生引擎能力，不改变 Generic 身份、分组、
Placeholder 或译文持久化契约。最终检查边界按[翻译验收指南](../../../docs/guides/acceptance.md)报告；
文本处理职责及外部发送范围始终服从任务发起者的明确约束。
