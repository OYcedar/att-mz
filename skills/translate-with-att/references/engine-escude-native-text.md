# Escude 封包查找、字库与原生界面

适用于使用 `ESC-ARC2` 等 Escude 资源封包、通过外部适配器接入 Generic 的游戏。先以目标构建的读取代码和资源确认具体版本结构。

## 1. 封包索引与二分查找

Escude 原生读取路径通常对封包目录索引使用区域相关的 ANSI 字符串比较进行二分查找：

- 重新封包时，目录索引条目的排序规则必须与引擎运行时的比较规则（大小写、代码页无符号字节序）严格一致，否则即使文件存在于包内也会查找失败。
- 封包后对所有条目执行模拟二分查找，确认均可准确命中且无代码页转换导致的别名冲突。

## 2. 字库映射与界面布局

- **编码与字库格位**：使用 Shift-JIS 字节索引自绘字库的引擎，不能只把脚本文本改成 GBK/UTF-8；脚本字符编码、字库格位索引、绘字与宽度测量必须遵循同一套映射规则。
- **字形与容量**：检查目标字符的字形边界与字距，避免越格污染相邻字符。核对姓名、选项、固定长度数据库字段的字节上限，按窗口宽度、续行缩进和禁则检查对白折行。
- **原生窗口与控件**：窗口标题、系统弹窗和原生控件可能绕过游戏内自绘字库直接调用系统 API，需单独核对 ANSI/Unicode 转换。
