# 大型、插件密集的 RPG Maker MV 翻译经验

## 适用结构与验证范围

本页整理混合插件参数、内联姓名控制码、组合写回和大量 QA 候选的处理方法。这些情况常见于
数万翻译单元、多插件和多界面的 MV 项目；遇到相同结构时按对应小节使用。

完整流程见[翻译 Skill](../SKILL.md)。每轮处理以当前原始来源、活动消费者、ATT 导出、工具报告
和实际写回差异为证据，并将证据保存在本次任务中。分别记录静态检查结果，以及人工启动游戏、
进入具体场景后确认的结果；未访问的界面继续列为待验证。

## 插件参数混合玩家文字与协议值

同一嵌套参数或 Survey 关系组中，标题、说明可能与内部编号、资源路径并存。先读关系组与成员样例
定位消费者，再检查各字段实际由哪些读取、绘制或查找操作使用；样例只帮助定位，不能证明整组都应翻译。

按[调查指南](../../../docs/guides/translation-project.md#2-调查可见文本)拆分混合决定，保留应排除字段
的原值和消费者证据。所有权与翻译语境分别判断：排除内部键后，相关标题和说明仍可属于同一语义组。
修改决定后重新生成计划，并从 Extract 继续核对新增位置。

截图发现漏翻时，用截图原文、场景和触发步骤搜索活动插件参数、源码及相关数据，确认具体显示位置。
核对该位置进入当前导出、写回后采用目标译文，以及协议字段保持原值。相同文字在其他位置的命中需
分别确认消费者；未确认场景保留 `unresolved` 和人工调查入口。

## 姓名藏在内联控制码中

原文含 `\N<...>`、`\NC<...>` 等形式时，先追踪活动消息插件的解析和绘制，确认内部文本确实是
人物姓名，并找一条外形相近但不应作为姓名处理的文本验证边界。语法与保护方式见
[RPG Maker 控制符规格](../../../docs/rpg-maker/rules.md#68-内建控制符)。

先核对当前 Extract 是否已把姓名投影为独立 Speaker。已独立提取的姓名修订对应条目；仍位于完整
文本中的姓名，确认前后壳受保护、内部姓名可翻译后，再修订该子段。使用 Survey 时，通过译前检查的
审核决定生成保护规则，具体顺序见[项目指南](../../../docs/guides/translation-project.md#4-extract)。

仅修订姓名时，按自然 ID 导出当前 Manual，保留原文、类型、正文和其他控制符，应用后核对实际写回
位置。静态往返可以验证这些字节与结构；姓名是否重复显示、跟随窗口或在回看中正确呈现，由人工在
对应场景确认。

## 组合写回后字面量位置变化

MV WriteBack 与 Generic 外部转换处理同一个文件的不同位置时，前面的译文可能改变后续字面量的
绝对字符位置。原始偏移与行号用于追溯来源；合并时还要用文件、字面量类型、原文、引号和相邻代码
重新确认唯一位置。无法唯一定位时回到来源调查。

确认全部映射后，将结果按本次确定的顺序合入隔离副本。对照原始来源、Generic 映射、ATT 输出和
最终文件，核对每个位置的唯一译文、JSON 或 JavaScript 解析结果，以及范围外资源和存档保持原值。
外部往返的检查入口见[验收指南](../../../docs/guides/acceptance.md#4-检查-writeback)。

## 静态 QA 候选较多

按[译文质量检查](../../../docs/guides/acceptance.md#3-检查译文质量)先查看摘要中的确定状态和未验证项，
再按原因审核 Review 组。源语言残留候选结合原文、当前译文和实际消费者，区分拟声、专名保留、
协议值与真实漏译。误纳入的协议值回到来源与所有权处理；需要改译的正文进入 Manual。

在 Manual 中集中修订并应用后，重新导出完整译文，复查受影响的术语、控制符和插件界面文本。
原文保留理由以当前语境为限；对未访问界面和仍缺消费者证据的位置保留具体人工检查项。
