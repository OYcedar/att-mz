# 大型、高插件 RPG Maker MV

## 适用特征和验证范围

适用于同时满足大部分下列特征的项目：翻译单元达到数万量级；活动插件和嵌套插件参数较多；
标准事件文字、插件界面、自定义数据和少量外部文本并存；剧情分支或地图较多；存在 MV 虚拟
姓名框或其他插件文字外壳。

当前经验已由真实项目验证完整的静态首次流程和正常标题启动：Survey、所有权、Extract、
Preflight、术语、Translate、集中 Manual、静态 QA、WriteBack、最终字体和正常启动；也已验证
根据用户截图定位插件界面漏翻并生成静态返修译本。返修后的实机结果、动态场景、窗口布局、
字体回退和全部剧情分支仍由用户确认。Survey、Rules、Placeholder、Generic 任务组织、Manual
或 WriteBack 的现行行为变化后，重新核对受影响步骤，不能默认旧经验仍适用。

## 已验证的首次翻译方法

1. 只运行一次 Survey，先读紧凑关系组；只有混合了玩家文字和协议值的组才按成员拆分。
   无法由静态证据确认的消费者直接保持 `unresolved`，`coverage.complete=false` 不阻止已确认
   范围继续翻译。
2. 游戏路径和目标语言确定、Init 不与当前磁盘工作争用时，在审核关系组期间并行执行 Init；
   Extract 必须等待计划定稿。不要为追求完整标志反复扫描或逐成员穷举。
3. Extract 后固定一份完整 Manual。立即启动术语作业，并在网络等待期间完成 Preflight；术语只
   保留需要全游戏统一译法的专名，普通词、资源名、短语和整句不纳入。
4. Translate 后先续跑仍可恢复的未完成任务。连续恢复已不再明显减少剩余项时停止模型重试，
   将超长任务、少量协议残留和精确 QA 问题合并成一次 Manual；Manual 默认直接 apply。
5. `rejected` 候选可以用少量显式重试收回可恢复结果；每次根据剩余量是否明显下降决定是否
   继续，收益下降后按自然 ID 集中修订。固定空白槽使用精确空字符串，不能用普通空格或人工
   哨兵进入最终译文。
6. 静态 QA 的大量启发式命中不能直接当作漏译。先读按原因压缩的 Review 组，只展开决定处理的
   组；确定问题直接进入集中 Manual。剩余无目标语言条目再按组确认是否为协议值、文件标记、
   坐标、拟声或有意保留内容，不逐条读取全部启发式明细。
7. 虚拟姓名框只在已经确认的外壳中翻译内部姓名。批量修订时按自然 ID 导出当前译文，只替换
   姓名子段，并核对正文、类型、原文和控制符均未变化。
8. 外部文本只有在消费者和写回方式都已确认时交给 Generic，并与 MV 位置保持唯一所有权。
   能独立理解和写回的记录各自成为 Group，不能把同一文件中的大量记录合成一个超长任务；
   合并结果后核对每个自然 ID、原文和类型没有变化。
9. 使用当前 ATT 一次 WriteBack 数万单元；成功后检查发布目录、日志、JSON 结构和原始来源未改。
   应用最终字体后必须按玩家方式启动隔离副本并取得正常标题或首个交互画面证据。用户明确禁止
   启动程序时，只能交付静态候选。动态插件界面、字体回退、裁切和未访问分支仍交给用户实玩反馈，
   不以一次启动或静态结果宣称全部场景通过。

## 用户反馈发现插件界面漏翻后的返修

1. 用户截图、场景和触发步骤可以证明该文字存在活动运行消费者，但只证明已经访问的界面。
   先按截图原文搜索 `plugins.js`、活动插件源码和相关数据，再确定唯一文本位置和所有者；不要把
   同一句英文在全游戏中的所有命中一起替换。
2. 能由 RPG Maker 插件参数规则可逆提取和写回的显示值归 Rules。补充所有权决定和规则后重新
   finalize、Extract、Manual、QA 与 WriteBack；Extract 新增的 Unit 必须进入 ATT 项目状态，
   不能只改最终 `plugins.js`。
3. 活动插件或 MV 核心 JavaScript 中硬编码的玩家文字，只有在消费者、精确位置和外部写回方法
   都已确认时归 Generic。每个能够独立理解和写回的字面量分别建立 Unit；写回覆盖层必须先验证
   全部映射，再一次生成，不能一边匹配一边留下部分结果。
4. Generic 调查记录的绝对字符位置属于原始来源证据。MV WriteBack 如果先改写同一文件前面的
   文本，后续字面量的绝对位置会移动；合并时用明确文件、行号、字面量类型、原文、引号和唯一
   命中重新确认。无法唯一命中时停止并重新调查，不降级为模糊或全局替换。
5. 把 Rules 与 Generic 结果合入新的 WriteBack 候选后，核对新译文存在、对应运行位置的旧值
   不再存在、修改过的 JavaScript 可解析、原版未改、字体运行时别名仍保留、用户存档逐字节未变。
6. 用户负责实机确认时，不启动游戏。交付时列出截图对应的复查入口，并明确本轮只修复已取得
   运行证据的漏翻，其他未访问插件界面仍保持未验证。

## ATT 与 Agent 的分工

- ATT 负责 Builtin、已批准 Rules、候选强校验、Rejected 状态、Manual 原子应用、来源快照和
  WriteBack 原子发布。
- Agent 负责非标准来源所有权、术语筛选、Review 判断、集中 Manual、静态 QA 分类和用户反馈
  定位；不得用最终文件直接改字绕过 ATT 项目状态。
