# 大型、高插件 RPG Maker MV

## 适用特征和验证范围

适用于同时满足大部分下列特征的项目：翻译单元达到数万量级；活动插件和嵌套插件参数较多；
标准事件文字、插件界面、自定义数据和少量外部文本并存；剧情分支或地图较多；存在 MV 虚拟
姓名框或其他插件文字外壳。

当前经验已由真实项目验证完整的静态首次流程：Survey、所有权、Extract、Preflight、术语、
Translate、集中 Manual、静态 QA 和 WriteBack。没有通过实际游玩验证动态场景、窗口布局、
字体回退和全部剧情分支；这些项目必须等待用户反馈。Survey、Rules、Placeholder、Generic
任务组织、Manual 或 WriteBack 的现行行为变化后，重新核对受影响步骤，不能默认旧经验仍适用。

## 已验证的首次翻译方法

1. 只运行一次 Survey，先读紧凑关系组；只有混合了玩家文字和协议值的组才按成员拆分。
   无法由静态证据确认的消费者直接保持 `unresolved`，`coverage.complete=false` 不阻止已确认
   范围继续翻译。
2. 游戏路径和目标语言确定、Init 不与当前磁盘工作争用时，在审核关系组期间并行执行 Init；
   Extract 必须等待计划定稿。不要为追求完整标志反复扫描或逐成员穷举。
3. Extract 后固定一份完整 Manual。立即启动术语作业，并在网络等待期间完成 Preflight；术语只
   保留需要全游戏统一译法的专名，普通词、资源名、短语和整句不纳入。
4. Translate 后先续跑仍可恢复的未完成任务。连续恢复已不再明显减少剩余项时停止模型重试，
   将超长任务、少量协议残留和精确 QA 问题合并成一次 Manual；Manual 默认直接 apply。
5. `rejected` 候选可以用少量显式重试收回可恢复结果；每次根据剩余量是否明显下降决定是否
   继续，收益下降后按自然 ID 集中修订。固定空白槽使用精确空字符串，不能用普通空格或人工
   哨兵进入最终译文。
6. 静态 QA 的大量启发式命中不能直接当作漏译。先分开处理 `rejected`、空译文、pending 和明确
   可见的源语言残留，再逐项确认剩余无目标语言条目是否为协议值、文件标记、坐标、拟声或有意
   保留内容。
7. 虚拟姓名框只在已经确认的外壳中翻译内部姓名。批量修订时按自然 ID 导出当前译文，只替换
   姓名子段，并核对正文、类型、原文和控制符均未变化。
8. 外部文本只有在消费者和写回方式都已确认时交给 Generic，并与 MV 位置保持唯一所有权。
   一个外部来源能按真实记录边界独立拆分时，在建立 Generic 输入时就拆成合理任务；合并结果
   后核对每个自然 ID、原文和类型没有变化。
9. 使用当前 ATT 一次 WriteBack 数万单元；成功后检查发布目录、日志、JSON 结构和原始来源未改。
   不启动游戏时，把动态插件界面、字体、裁切和未访问分支明确交给用户实玩反馈，不以静态结果
   宣称全部场景通过。

## ATT 与 Agent 的分工

- ATT 负责 Builtin、已批准 Rules、候选强校验、Rejected 状态、Manual 原子应用、来源快照和
  WriteBack 原子发布。
- Agent 负责非标准来源所有权、术语筛选、Review 判断、集中 Manual、静态 QA 分类和用户反馈
  定位；不得用最终文件直接改字绕过 ATT 项目状态。
