# TyranoScript／Electron ASAR 汉化与补丁经验

## 适用结构与证据边界

适用于 Electron 应用从 `resources/app.asar` 加载 TyranoScript 场景、配置和网页界面的任务。
先确认应用入口、`data/scenario/*.ks`、`data/system/Config.tjs` 与 `tyrano/plugins/kag` 的
实际读写关系；不能仅凭 `.ks` 扩展名套用 Kirikiri 流程。

本经验来自真实材料的提取与反向映射、原游戏解析器对账、JavaScript 语法检查、字体字符覆盖、
ASAR 重读，以及干净副本上的补丁安装、重复安装、版本拒绝和回滚验证。它们不证明真实场景的
排版、存档恢复、语音播放或显示器 HDR 输出正常。本文也不表示 ATT 已有 TyranoScript 原生
适配器；引擎层负责容器、提取、反向转换和发布，ATT 通过 Generic 管理翻译与验收。

## 调查显示消费者与提取范围

- 先追踪 `package.json` 的入口、主进程加载的页面、场景加载器及活动插件，建立每类可见文本的
  来源和写回位置。原版保持只读，续跑使用已有处理副本与 ATT 状态。
- 正文之外检查选择项 `glink.text`、`ptext.text`、`tb_ptext_show.text`、按钮提示、系统提示、
  显示姓名和可编辑姓名的默认值。字段名只是调查入口，是否翻译由实际显示消费者决定。
- Builder 的 `tb_start_text`／`_tb_end_text` 等块可以提供语境边界，但要按实际方言解析。
  保持场景自然顺序，把共同决定含义的正文、提示和选项交给同一完整语境；独立记录分别成组。
- JavaScript 字面量用匹配语法版本的 AST 定位，再沿变量、语言表及 DOM 调用追踪显示来源。
  简单引号扫描会把正则字面量、注释和转义误认成文本；不要按“字符串包含源语言”全量替换。
- `#name`、角色注册、语音配置、宏和效果参数可能共用姓名查找键。区分内部姓名与显示姓名；
  在真正的显示调用处使用 ATT 输出的显示映射，保留语音计数、资源路径及角色身份。
  修改显示参数之前检查它是否还被语音或特效使用，不能只看到 `.html(...)` 就覆盖上游值。
- 尚无消费者证据的来源保留 `unresolved`。图片文字、资源名、跳转标签、条件表达式和内部键
  分别处理，不用已登记译文的完成率代替覆盖调查。

## 稳定映射与 Generic 交接

遵循现行 [Generic JSONL 规格](../../../docs/generic/jsonl.md)和
[TaskBlock 规划](../../../docs/translation/task-planning.md)，不在引擎经验中另立协议。

- 用稳定的 Group／Unit 身份关联可精确写回的来源。文件位置、源摘要、编码、BOM、换行和
  替换跨度保存在引擎内部映射中，不向 Generic 增加 metadata、context 或私有字段。
  有外部 SExtractor 交接时同样保留独立反向映射，不让交接格式承担全部写回信息。
- 映射坐标必须对应提取时的准确物理基线。文本读取自动把 CRLF 转为 LF 后，旧跨度可能已经
  失效，即使条目内容与身份仍正确。只对交给 Generic 的文本做契约要求的换行转换；保存原文件
  的坐标体系和重建方式，写回前验证基线未漂移。
- JavaScript AST 的 UTF-16 位置、语言运行时的 Unicode 字符位置与 UTF-8 字节偏移不能混用。
  存在非 BMP 字符时显式转换；不能从某份材料没有这类字符推导出以后无需转换。
- 属性捕获排除结束 `]`、引号和其他分隔符。替换后按当前 Tyrano 解析器验证字段值，检查未加
  引号值、空格、引号与实体处理。某些方言会改写 `#` 或 `=`，因此 HTML 实体转义也未必安全。
- 源摘要变化、跨度重叠、身份缺失或重复、捕获无法唯一定位时停止该次发布，修复映射后继续；
  不根据相近字符串猜写回位置，也不因提取器修正就丢弃全部已有译文。

## 控制保护、状态与结构返修

保护规则按 [Placeholder 规格](../../../docs/translation/placeholders.md)建立。
Generic 没有引擎内置控制保护，必须调查实际 Tyrano 标签、宏、插值和 HTML wrapper。

- 翻译前保护不能改写的片段，保持正文为 NaturalText。不得把含源语言的正文一起保护以消除
  QA 报告，也不得把模型生成的补充语句视为控制符。
- ATT 状态与引擎覆盖分别对账。NoWork、Complete 或退出成功不证明未提取的菜单已翻译，
  也不证明反向转换和部署成功。按照当前语言规则区分可翻译的剩余项、Rejected 与纯标点等
  非语言内容；汉字文本也需按真实语言判断处理，不能只用假名扫描决定翻译范围。
- 源语言残留检查针对保护段之外的自然文本，排除已确认内部键。孤立长音符、中点等符号与
  连续词语分别判断；不要用宽泛允许名单消除真正的残留。源文件没有而译文出现的 `U+FFFD`
  应回到译文或编码链调查，不能靠补字体掩盖。
- 标签身份、数量、相对顺序通过后，继续检查正文位于标签之间的哪个文本槽。正文移到 `[p]`
  后、移出字体 wrapper，或移到角色宏之前，都可能改变显示或解析结果。
- 以目标构建实际使用的场景解析器比较命令顺序、非显示参数、label／jump 关系和文本槽拓扑。
  可用隔离的解析 harness 提供必要依赖桩，避免直接执行应用入口或场景脚本。解析通过只证明
  结构；如果存档或恢复逻辑依赖命令索引，再明确检查对应索引，不能据此宣称读档已实测。
- 不盲目要求所有原始 AST 节点全等。先确定目标构建依赖的结构约束，再定位首个违反约束的
  来源与条目。已确认跨控制边界的正文通过 ATT 定向返修，必要时把控制间的自然文本分别
  建立可逆映射，保留原上下文；不要由适配器自行撰写译文。
- 定向重试需要邻近上下文时使用现行 Generic 契约表达关联，只导入目标修订，保留已确认的
  上下文译文。按真实诊断重试剩余或被拒项；永久额度或鉴权错误时保留进度并处理服务阻碍，
  不无限重试或擅自切换模型配置。

## 字体与有效加载关系

- `Config.tjs` 的默认字体不一定覆盖 ptext、直接 CSS 或特效文字。沿 font-family、font-face、
  字体文件路径和局部覆盖找到实际消费者，保留原字体别名、符号字体与后备项。
- 对最终部署文本的完整字符集检查字体 cmap；缺字来自译文替换符时先修复文本。字符覆盖
  不证明浏览器已经加载该字体，也不证明行高、换行、描边与裁切正确。
- 只修改已确认的字体加载关系，随重分发字体携带所需许可证。人工场景检查覆盖正文、选择、
  姓名、系统界面和特殊符号，不能只以标题正常作为全局字体验收。

## 大型 ASAR 的回填与发布

Electron 把 ASAR 作为虚拟目录读取；把松散脚本放到旁边，并不自动成为归档内路径的覆盖层。
容器语义参考 [Electron ASAR 指南](https://www.electronjs.org/docs/latest/tutorial/asar-archives)
与 [ASAR 实现及格式说明](https://github.com/electron/asar)，具体版本与字段按目标构建核对。

- 大型归档按索引 seek 并分块读写，不把整份归档加载到内存。核对 Pickle 外层长度、JSON 的
  UTF-8 长度、对齐、payload 基址以及条目的 offset／size，使用足够宽的整数并检查越界。
- 调查 link、unpacked 与完整性元数据。外置文件需保留匹配的 `.asar.unpacked` 关系；启用了
  [ASAR integrity](https://www.electronjs.org/docs/latest/tutorial/asar-integrity) 或相关 fuse 的
  构建不能直接套用只改索引的方案，需验证匹配的完整性和发布机制。
- 候选归档完成后独立重读全部索引、修改条目与未修改条目，核对 entry 集合、内容及非目标
  元数据。重新执行场景结构与 JavaScript 语法检查，不能只校验解包目录里的脚本。
- 写入独立候选，校验通过后再备份并发布。运行中的应用可能持有旧句柄或缓存，正常退出后
  才替换；不要强制终止用户进程，也不要把热替换后的字节读回当作应用采用新内容的证明。
- 启动配置、字体和其他已授权修改进入引擎的重建输入或明确合并阶段，避免下一轮 WriteBack
  丢失。所有阶段沿用只读原件和已有处理副本，不用原版覆盖续跑成果。

## 明确要求 SDR 或报告 HDR 色彩问题时

这属于应用启动与渲染调查，不能因汉化而自动修改。记录目标 Electron／Chromium 版本，检查
其支持的色彩与 HDR 开关，在主进程 `ready` 之前注册并保留已有启动配置。调用时机参考
[Electron 命令行开关文档](https://www.electronjs.org/docs/latest/api/command-line-switches)。

真实材料中使用了 `force-color-profile=srgb`、`force-raster-color-profile=srgb`，以及
`disable-features` 中的 `UseHDRTransferFunction`、`EnableExternalDisplayHDR10Mode`。
该记录仅有语法、静态注册与注册顺序证据，尚无显示器输出证据；这些名字也不是所有 Chromium
版本的稳定接口。下一次任务先核对目标版本支持，再选择必要项，合并原有 disable-features
而非覆盖已有列表。未知或未生效开关不能算成功修复。

改动纳入可重复重建的启动输入，随下一次正常启动生效。分别报告静态注册、实际进程参数和
物理显示结果；不把应用参数等同于关闭 Windows HDR／Auto HDR，也不扩展为系统设置修改。

## 请求独立补丁时

完整 ASAR 往往包含大量图片和音频。需要小型补丁时，可交付修改／新增文件与重建配方，从
使用者匹配版本的归档流式取得未修改内容；先验证这种方式能重建当前权威处理产物。

- 安装前校验实际版本所需的归档和启动程序，不匹配时在修改前拒绝。配方检查路径、偏移、
  大小与分块内容，重建后校验整个结果；只比较源文件大小不能证明版本一致。
- 明确选择“字节完全一致”还是“条目内容与语义一致”。前者还要处理索引之外的 gap／孤立
  字节，并审查补丁载荷，避免把未引用的大量游戏媒体当作必要差分；后者不能声称整档哈希
  与已验证产物相同。
- 临时结果校验成功才发布，备份与恢复校验独立进行。重复安装、已有备份、不匹配版本、
  失败中断和回滚有确定行为；只清理本次创建的临时文件，不覆盖未知备份。
- 如果检查游戏是否正在运行，按实际可执行路径确认归属，不按进程名批量终止。存档和用户
  配置用安装前的当前状态作为保留基线，不用早期提取快照覆盖用户后来产生的进度。
- 从只读原件建立干净测试副本，验证安装产物、未修改文件与存档、重复安装、拒绝错误版本
  以及恢复原件，再检查最终压缩包 CRC 和解压后的补丁载荷。安装器依赖按交付环境说明；
  自包含方案仍要在目标环境验证，不能依赖作者机器已有的 Python、Node 或其他运行时。

交付分别说明 ATT 翻译状态、实际显示来源覆盖、结构和字体静态结果、安装器验证，以及人工
实机仍需检查的正文、选项、姓名／语音、系统界面、存档恢复与色彩场景。安装器运行通过不等于
游戏已经正常游玩；只要求整理经验时，不为补齐这些栏目重启翻译或游戏测试。
