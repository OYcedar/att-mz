# 同类游戏翻译方法

本专栏保存已经由真实翻译过程和用户反馈确认、能够复用于一类游戏的方法。先按游戏结构选择
最接近的一节；条件不符合时回到主 Skill，不把这里的经验强套到当前项目。

每次补充都写清：类型特征、首次翻译方法、用户实玩重点、常见反馈的复查方法和不适用条件。
不记录游戏名、项目路径、具体文本、一次性规则或尚未验证的猜测。

## 标准事件文字为主的 MV/MZ

- 类型特征：主要玩家文字位于标准数据库和事件命令，非标准插件文字很少。
- 首次方法：优先使用 Builtin；Survey 只处理确实出现的非标准来源，不为少量未知项扩大调查。
- 实玩重点：对话、选项、滚动文字、菜单、战斗消息、存档和设置界面。
- 反馈复查：按场景和自然 ID 集中导出一份 Manual，修正后只重跑 WriteBack 与受影响场景。
- 不适用：主要界面或剧情由插件、自定义 JSON、动态脚本生成。

## 插件和自定义数据较多的 MV/MZ

- 类型特征：活动插件参数、自定义 JSON、脚本字符串或多个字段共同产生玩家文字。
- 首次方法：用 Survey 的关系组确认消费者；只为已确认位置生成 Rules，未知消费者保持
  `unresolved`。不要逐插件反复扫描，也不要手写大量 Rules 对象。
- 实玩重点：插件菜单、任务日志、图鉴、设置页、动态提示，以及静态调查无法进入的分支。
- 反馈复查：先判断是漏提取、错误所有权、错误译文还是运行显示问题，再分别更新 Rules、
  Manual 或 QA；不要用翻译返修掩盖漏提取。
- 可复用工具：同一种插件协议或数据容器反复出现，并由实际消费者和写回结果确认后，可以在
  Python 工具箱增加面向该协议的助手；Rust 不增加插件名分支。
- 不适用：只因文件名、变量名或文本外形相似，尚未证明消费关系。

## 分支多、地图多或文本量大的剧情游戏

- 类型特征：事件数量大、分支难以一次游遍，静态文本覆盖远大于首次实玩范围。
- 首次方法：一次 Survey 后按紧凑关系组决定，不展开完整位置清单；先交付结构完整的译文，
  不等待所有剧情分支都被运行观察。
- 实玩重点：章节切换、选择分支、公共事件、长对话断行和跨地图重复称呼。
- 反馈复查：用户提供场景和可辨认原文后，定位精确自然 ID，合并成一次 Manual；未访问分支
  保持 `unverified`，不伪称已经通过。
- 不适用：文本量小且所有场景可以在首次验收中完整访问。

## 界面、任务系统或日志显示较多的游戏

- 类型特征：短标签、列表项、说明、任务状态和日志大量出现在受限窗口或插件界面。
- 首次方法：语言、术语和结构校验与布局检查分开；宽度、截断、字体回退和未知消费者只进入
  Review，不拒绝结构合法译文。
- 实玩重点：不同分辨率下的菜单层级、任务列表和详情、滚动区域、选项切换及长短状态变化。
- 反馈复查：根据实际窗口和文本定位修改译文，再复查同一关系组中的称呼；不要在 WriteBack
  中自动压缩或改写正文。
- 不适用：没有受限 UI，或相关窗口尚未实际访问。

## 标准提取与 Generic 混合

- 类型特征：标准 MV/MZ 内容之外，另有经确认需要外部过程读写的文本来源。
- 首次方法：为每个位置确定唯一所有者；标准位置由 Builtin/Rules 管理，Generic 只接收证据
  完整且能精确往返的位置，禁止重复拥有。
- 实玩重点：两个来源合并后的显示顺序、同步字段和外部写回结果。
- 反馈复查：先判断问题属于哪个所有者，再在对应项目修订；不能在最终文件中直接改字后绕过
  ATT 状态。
- 不适用：缺少精确消费者或没有安全、可验证的 Generic 写回过程。
