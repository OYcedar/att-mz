# RealLive 原生文字与姓名回填

适用于 `Seen.txt`、SEEN 脚本与 `Gameexe.ini` 形式的 RealLive 游戏，通过外部适配器接入
Generic 时读取。以下方法来自真实脚本、原生解释器分支和返修后的封包检查；不同构建仍需
核对实际消费者，不把具体游戏地址或补丁偏移复用到另一款游戏。

## 姓名控制与显示值

先确认对白前缀 `【姓名键】` 的原生控制语义。已确认的读取路径会先处理未引用姓名段，
再进入正文字符串；把姓名和正文整体包进 ASCII 引号，会让姓名成为普通显示文字。

- 内部姓名键保留，与可翻译的显示名分别建映射；保护键不表示已经验证显示结果。
- 编码时保留姓名控制前缀在引用状态之外，只引用正文。
- `#NAMAE` 记录要按目标构建的原生加载格式检查完整字段。仅有键和值的新增行可能被跳过；
  参数段同时影响语音关联，不能从另一角色复制参数。
- 最终封包先检查原始字节和引号状态，再解析姓名键到显示名；残留与布局检查使用最终显示名，
  不能先剥掉姓名标签再宣布可见文本已覆盖。

至少选择普通带姓名对白、原译文相同而可能跳过重写的短句、新增姓名映射和有语音关联的角色
作为区分边界的样本。核对全部使用键都能被原生配置读取，并与当前审校译名一致。

## 编码与原生界面

中文字符映射需要覆盖脚本读取、测量和绘制各条路径。原生静态资源正常，不证明动态窗口标题、
控件文字和列表项正常；分别追踪窗口创建、后续文字设置及控件消息中的字节到 Unicode 转换。
旧控件结构按实际 ABI 读取字段，不假定其大小与当前 SDK 一致。

批量翻译前调查代码页、系统语言、时区等启动检查。检查原生条件和实际调用后再确定兼容办法，
不要把字体代理已安装当作全部启动条件已经满足。

## 脚本与返修验证

正文变长时，原生入口、全部跳转与相关定位必须按实际格式重建；解析器接受仍不足以证明
原生执行一致。针对既有脚本的后续补丁，先明确是否需要保持脚本地址和存档引用，再选择
等长修改或完整重定位。不能把某次等长返修有效推广成所有文字必须等长。

使用[外部适配器验收](../../../docs/generic/adapter-verification.md)冻结最终脚本、配置、
编码映射、字体和代理，将姓名语义、参数加载与字节边界作为消费者检查。补丁后重新读取最终
交付资源，并核对本轮范围外修改和存档。实机清单包含姓名框、语音、动态设置标题及场景进出。
