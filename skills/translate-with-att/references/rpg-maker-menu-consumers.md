# RPG Maker 命令名称的真实消费者

活动插件修改标题、菜单、设置或战斗指令列表，或实玩截图出现命令名称漏翻、指令消失时，
使用本页核对来源覆盖。

## 从命令列表回溯显示值

按实际插件加载顺序查找命令列表的构建、追加、替换与重排，包括 `makeCommandList`、
`addGeneralOptions`、`addVolumeOptions`、`addOriginalCommands`、`addCustomOptions`，
以及直接修改 `_list`、条目 `name` 的代码。既检查 `addCommand`，也检查 `splice`、`push`
等插入方式。只找显示调用中的字符串字面量会漏掉变量传入的名称。

将 `addCommand(variable, symbol)` 和 `{ name: variable, ... }` 的名称沿赋值回溯到
`PluginManager.parameters`、包装 getter、别名、默认值和嵌套结构。参数是否可翻译由最终
显示调用决定；参数名像开关或启动行为，不证明其值是布尔值。同一功能的字符串名称、技术
symbol、handler 和布尔状态分别有自己的用途，不应一同改写。

自定义选项还可能通过 `Name`、枚举显示值、确认按钮名称生成文字。非空名称即使当前受条件
隐藏，也要核对未来可见场景；空列表、空名称和实际不生成命令的分支分别记录。名称兼作
查找键时，确认反向转换能保持调用方与查找关系，再确定可逆所有者。

## 备注协议中的类型与显示名称

插件可能把同一条备注拆成命令类型、排序、显示名称、图标和帮助查找键。某个字段使用源语言，
不证明它是文案；先核对解析器取出的槽，以及它进入 symbol 分派、ID 查找还是显示调用。
例如消费者确实按 `<command:kind,order,caption,icon>` 解释备注时，第一项是协议类型，
第三项才是显示名称。不能把首个看起来像自然语言的项交给模型，再以提取和翻译成功证明安全。

只捕获已确认的显示槽，按 [Extract Rules](../../../docs/rpg-maker/rules.md#4-extract-rules)
保留其余字节为 Literal。当前规则无法表达结构或多个用途的同步关系时，建立 Generic 外部映射。
扫描消费者实际读取的同类备注，包括角色、职业、装备、状态或技能中已启用的来源；不将一个插件
的字段顺序推广为所有备注协议。

原版可见而译后指令消失时，先比较类型、symbol、ID、排序及过滤条件，再检查文字与字体。
用原版和译后数据分别执行实际命令构建代码，核对条目数、顺序、启用状态及图标。发现类型被误译，
恢复原版协议值并修正提取规则、生成器与 ATT 当前状态，不能只手工改发行文件而让下次 WriteBack
重新破坏它。

## 图片中的命令名称

数据库或插件参数已是译文，而画面仍显示原文时，核对按钮是否加载图片，及普通、选中等状态
是否分别使用资源。图片文字属于图像翻译流程；建立显示名称与实际加载资源的对应关系，不把
资源名、按钮动作或状态键当成文字改写。

编辑后保持原尺寸、透明背景、状态对应与动态数值图层。对局部编辑核对允许区域外的像素；
加密资源还应通过当前引擎的实际解密函数核对结果。图片回读与像素检查仍不能代替游戏内的
普通和选中状态验收。

## 与 ATT 状态及部署对账

为已确认的显示位置保存来源字段、显示调用、技术 symbol、可见条件、ATT 自然 ID 和部署
位置。按当前 Rules 或 Generic 合约纳入提取，不用注释、编辑器参数说明或 Survey 候选代替
正式所有权。少量补提取沿现有项目继续，核对未变来源的既有译文得到保留。补提取改变 Group
语境时，按 [Extract 的继承规则](../../../docs/rpg-maker/extraction.md#4-冲突继承和提交)
核对自动译文适用性；保留了正文，不代表它仍是 Current。

补译后检查 remaining、rejected、WriteBack，回读发行文件并确认参数值等于 ATT 输出；保留
参数键、symbol、handler、资源路径和数值配置。已登记译文全部 current 或无源语言字母，只
说明登记集合的状态，无法发现尚未登记的菜单参数。

通过实际插件代码构建命令列表，可确认最终名称确实来自已部署的参数，并核对命令和条件
保持原样。这属于结构检查；文字裁切、字体和实际可见性仍以对应游戏窗口为证据。报告明确
区分两种验证范围。
