# 制作游戏术语表

## 读取现行规则

开始任何候选发现、判断、定译、审查或汇总前，完整读取
[通用术语规则](references/terminology-rules.md)。该文件是本 Skill 对术语身份、收录条件、
证据、固定写法、变体和验收的唯一权威；不要在作业提示词或临时说明中另建一套规则。

处理 RPG Maker MV 或 MZ 时，再完整读取
[RPG Maker MV/MZ 术语抓取参考](references/rpg-maker-mv-mz.md)。该参考只说明候选来源和
核查方法，不改变通用术语规则。

只审查一份已经很小的现有术语表时，可以由当前 agent 直接应用通用规则。从完整游戏语料
发现候选时，默认使用本发行包内的 Formic；Formic 只负责分片候选发现和定向查证，最终
纠错、跨单元去重、定译与导出仍由当前 agent 或明确指定的外部处理者负责。

## 确认输入与结果

先确认游戏或作品版本、源语言、目标语言、玩家可见语料的完整范围、已有官方资料、用户
指定译名和最终消费者。缺少会改变收录、适用范围或固定写法的事实时，先补齐材料；不能用
目录名、未使用资源或猜测冒充实际语料。

最终先形成与工具无关的术语工作记录。只有消费者是 ATT 时，才在完成统一验收后完整读取
发行包中的 `docs/translation/terminology.md`，把已确认且能够由 ATT 当前全局作用域表达的
条目转换成严格 TOML。不要让下游字段反向决定候选范围。

## 建立 Formic 作业

1. 以当前 Skill 所在的发行目录为准，确认同一发行根中的 `tools/formic/formic.exe`、
   `tools/formic/config.toml` 和随工具发布的使用说明完整可用。不要混用其他安装或旧版本。
2. 在发行目录外选择一个尚不存在的作业目录，运行
   `scripts/new-formic-job.ps1`。该脚本建立固定结构，并复制本发行版的任务模板、结果 schema、
   作业上下文模板和术语规则快照；不得把作业数据或结果写回发行目录。
3. 把全部主动发现语料放入 `input/corpus/`。保留自然可读的源文件、记录、字段或行号以及
   判断身份所需的上下文。需要按行区间规划时，使用一行一个完整自然文本记录的 UTF-8
   JSONL；不要按字节或任意行数切碎同一语义对象。
4. `input/reference/` 只保存作业上下文、规则和用于验证的材料，不是主动发现范围。完整填写
   `reference/job-context.md`，删除所有待填写标记；真实凭据不得写入作业文件。
5. 由当前 agent 或外部程序制定 `plan.jsonl`。每个单元必须语义独立，能够只依靠共同任务、
   当前分片和只读证据完成；计划只能覆盖 `corpus/`，并且必须恰好覆盖全部 corpus 一次。
6. 运行 `scripts/validate-formic-plan.ps1`。校验失败时先修正语料或计划，不启动 Formic。

作业目录固定为：

```text
<job>/
├─ input/
│  ├─ corpus/
│  └─ reference/
├─ plan.jsonl
├─ task.md
├─ result.schema.json
├─ out/
└─ final/
```

## 运行与恢复

Formic 只读取进程当前工作目录中的 `config.toml`。从本发行包的 `tools/formic/` 作为 cwd
启动程序，并为 `--data`、`--plan`、`--task`、`--out` 和 `--output-schema` 传入作业目录中的
绝对路径，默认传入 `--concurrency 64`。只有模型服务公布的配额、明确限速或已经复现的服务
拒绝要求更小窗口时才降低并发；确认服务与机器支持更高并发时可以提高。不要用 1 作为缺少
资料时的保守默认。

启动前确认配置中没有未替换的占位值，`FORMIC_LLM_PROTOCOL` 和所需凭据环境变量已经设置，
外部工具只暴露本次验证需要的只读能力。任务说明不能把自然语言当成权限控制；无法确认工具
是否只读时不要向 worker 暴露它。

按照工具随附说明解释退出码和运行记录。部分单元失败时保留已经发布的数字编号 JSON，依据
原始完整计划只为缺失单元生成剩余计划并重跑；不要清空输出，不要让 worker 读取 output
协商去重或完成顺序。启动配置或输入无效时先修正同一事实，取消时报告已经完成和未完成的
自然编号。

## 校验并统一汇总

所有计划单元都已有结果后，使用原始完整计划运行
`scripts/validate-formic-results.ps1`。该脚本确认结果完整、schema 一致，并证明每个候选的主动
发现锚点确实属于自己的分片；跨分片或外部资料只能成为该候选的变体、支持证据或反证。

校验通过后，当前 agent 或外部处理者重新使用通用术语规则读取全部单元结果：

1. 纠正错误身份、错误固定写法和证据误读；
2. 按身份与适用范围合并，不按原文字符串机械去重；
3. 回查全部原文变体、同形异义、短词和子串风险；
4. 把 `include`、`exclude` 和 `needs_review` 当作单元建议，而不是最终状态；
5. 只把已确认条目写入成品，另行保留拒绝理由、冲突和待确认事项；
6. 按通用规则完成整份术语表验收，再根据实际消费者转换格式。

任何计划单元缺失、锚点越界、规则材料不一致或关键冲突尚未处理时，都不能把现有结果称为
完整成品。
