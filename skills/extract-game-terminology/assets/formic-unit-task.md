# 单元目标

只从“你的分片”主动发现游戏术语候选，核实其身份、定义、固定写法和反证，并提交供外层
统一审校的单元记录。你提交的是建议，不是最终术语表。

# 必读材料

开始处理分片前，使用 input 范围的只读能力完整读取：

- `reference/terminology-rules.md`
- `reference/job-context.md`
- 数据集文件清单中存在 `reference/rpg-maker-mv-mz.md` 时，再完整读取该文件

使用其中的术语判断、证据、定译和变体规则。不要执行其中要求全局合并、最终导出或验收
整份术语表的步骤，那些工作由外层处理者负责。若 `job-context.md` 仍含待填写标记或与当前
分片明显冲突，使用 `needs_review` 保存受影响候选，不要自行补造作业事实。

# 范围

- 当前分片是唯一的主动候选发现范围。
- 每个候选必须至少有一个位于当前分片内的 `anchor`。
- 可以搜索完整 input 或调用已配置的只读外部工具，但只能验证当前分片已经发现的候选。
- 查证时发现的新表达不得成为本单元的新候选；它只能作为当前候选的变体、支持证据或反证。
- 不读取 output，不根据其他 worker 的结果去重、认领对象或判断全局完成情况。

# 查证

- 核实候选在游戏中的身份或定义、同形异义、已经存在的固定写法和可能冲突。
- `anchor` 使用 input 相对路径、从 1 开始的物理行号和该行中的精确原文片段。需要时使用
  input 搜索取得可复查行号。
- 其他 input 证据记录相对路径、行号、原文片段和它支持或反驳的事实。
- 外部证据记录可复查的地址或稳定定位、来源类别、支持或冲突关系和事实摘要。
- `include` 至少需要一项不在 anchor 所在位置的 input 支持证据，或一项外部支持证据；只有
  分片内单次出现而无法取得独立支持时使用 `needs_review`。
- 取得足以应用术语规则的直接证据并完成一次冲突检查后停止。工具不可用、证据不足或
  证据冲突时使用 `needs_review`，不要猜测。
- 只调用只读工具；不要修改本地或远端状态。

# 输出含义

- `include`：本单元建议收入，且能够负责地给出 `fixed_form`。
- `exclude`：已检查的疑似候选不满足术语规则。
- `needs_review`：身份、适用范围、固定写法或证据仍不足或互相冲突。
- `fixed_form` 无法负责确定时使用空字符串。
- `variants` 只记录已经发现且与当前候选有关的原文形式；不将它们提升为新的候选。
- `anchors`、`variants` 和 `input_evidence` 中的 path 都是相对于 input 根、统一使用 `/` 的路径。
- 允许 `candidates` 为空。
- 不输出 unit、总单元数、全局合并组、最终排名、全局统计或运行信息。

# 完成条件

当前分片中的合理候选均已按权威规则检查，每个候选都有分片内来源，结论有证据或明确的
不确定状态，并符合结构化输出契约后立即提交。
