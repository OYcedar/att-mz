# VX Ace／RGSS3 游戏汉化

沿用 [ATT 翻译主线](../translate-with-att/SKILL.md)，补充本引擎的外部提取、写回与显示检查。
当前通过 Generic 接入；本技能不表示 ATT 已有原生 VX Ace 命令域，也不提供适用于所有游戏的
解包器或消息插件。操作落在汉化副本，原版保留为只读基线。

## 任务范围与美化触发

默认完成用户要求的汉化或返修，保留现有视觉设计。缺字、乱码、断行、溢出、对齐和帮助容量
问题属于正常汉化修复，不需要先开展美化。

**只有用户主动明确要求美化、现代化或重做对话框／姓名牌等界面时，才启用美化流程。**
普通汉化、读取本技能或反馈排版错误都不自动开启美化。用户没有提出时，不主动建议或询问
是否美化，不替换皮肤、视觉主题或姓名显示层级。其他游戏曾经获得的美化授权不自动沿用。

用户只询问可行性时先作评估；已经明确授权当前对象的美化及后续修改时直接在该范围内推进，
无需重复确认。满足这些条件后，才读取并执行
[消息界面现代化](references/message-ui-modernization.md)。

## 确认引擎与读取方

核对 `Game.ini` 的运行库与脚本路径、`.rvdata2` 数据、`Scripts.rvdata2` 及可能存在的
`.rgss3a` 归档，确认实际版本与加载来源。VX Ace 的 RGSS3 基于 Ruby 1.9.2，
见[官方产品说明](https://www.rpgmakerweb.com/products/rpg-maker-vx-ace)。

- XP、VX、MV、MZ 的运行库和数据格式分别判断；本技能的 RGSS3 方法不直接套用到其他版本。
  MV/MZ Survey 不负责解析 VX Ace 的 Marshal 数据。
- 核对归档与松散文件的实际读取关系，保留游戏运行所需的图像、音频、运行库和外部配置。
  只有解包目录或同名输出文件存在，还不足以确定运行中加载了它。
- 新版 Ruby 可以承担离线读写工作；注入游戏的脚本须符合该游戏 RGSS3 的语法与 API。
  宿主的 `ruby -c` 或解析器通过，只记录为语法初筛。

## 建立可逆的文本映射

生成输入前读取 [Generic JSONL 规格](../../docs/generic/jsonl.md)，执行各阶段时沿用主技能的
Init、Extract、术语、Translate、Manual、QA 与 WriteBack。所有权与定位资料留在外部映射中，
不扩展 Generic 字段，也不把整个游戏脚本作为待译正文。

先选包含数据库字段、普通对白、选项／帮助和脚本文字的代表性材料，完成不改值的读取、重建和
再读取。核对类名、实例变量、数组与 Hash、数值、字符串编码、对象关联和自定义序列化负载。
`Table`、`Color`、`Tone` 等不能被替换成空对象后写回；未编辑的负载应按实际格式完整保留。
Marshal 的格式版本与 Ruby 版本分别核对，
参见 [Ruby Marshal 文档](https://docs.ruby-lang.org/en/2.0.0/Marshal.html)。

从最终显示消费者确认范围：

| 来源 | 提取与写回判断 |
| --- | --- |
| 数据库字段 | 区分名称、说明、备注中的显示正文与标签、资源键、公式、ID |
| 事件消息 | 追踪 `101/401` 消息头及正文，保留头像、背景、位置、缩进和事件顺序 |
| 选项与帮助 | `102` 选项及其实际帮助消费者共同检查；`108/408` 注释只有确实被插件用于显示时才作为正文 |
| 滚动文字 | `105/405` 的显示尺寸、字号和滚动行为单独核对 |
| Ruby 脚本 | 追踪 `draw_text`、`draw_text_ex`、词汇表和插件界面；资源路径、控制协议及代码骨架保持原义 |

按真实场景组织有序 Group，将完整消息块保留为可精确写回的文本范围，不按每条渲染行独立翻译，
也不把整个公共事件文件装成单一语境。映射保存来源文件、对象路径、事件块或字面量位置、原值和
来源核对依据；ID 与自然顺序在同一来源未变时保持稳定。

原文把姓名写在消息首行或正文前缀时，在外部映射中明确姓名与对白的边界。能够独立写回时，
将姓名和正文作为同一语境组内的独立 Unit；必须整块处理时仍保留姓名范围的来源依据。
译后分别判断“姓名是否存在”和“译名是否统一”：译名不同不能当成姓名缺失后再追加一份。
已有姓名在原位置统一，只有确认缺失才补回；无法确认边界时进入审阅，不给整块正文套引号来凑结构。

脚本正文按字面量边界处理 Ruby 引号、反斜杠、插值和 heredoc，不能对整段压缩源码做盲目字符串
替换。事件正文行数变化时按原块重建文本指令，避免后续位置漂移，并核对非正文指令和分支结构。

## 字体、编码与排版

先核对当前字体文件的 family、字符覆盖、注册方式和实际消费者。选择字体可沿用主技能的
[随包字体资源](../translate-with-att/SKILL.md#7-字体与封包)，具体注册和引用方式按 RGSS3 处理。

- 私有字体需在使用它的字体对象创建前可用；进程私有注册不修改系统字体设置。
  `Font.exist?` 核对引擎识别的 family，文件名不能代替 family 名称。
- Windows 路径按读取方的真实编码转换；不要把 RGSS 返回的系统字节路径直接当作 UTF-8。
  可行时用 ASCII 相对字体路径调用宽字符注册接口，并保留原生回退字体或专用符号字体。
- Marshal 字符串、Ruby 源码和 `Game.ini` 分别按实际读取方保存编码、BOM、换行与转义，
  不因目标是中文就把全部文件统一转成 UTF-8。
- 字号不是汉字推进宽度。依据 `Bitmap#text_size`、绘字实现，或已用代表性证据校准的后台字体度量
  计算行宽；扣除内边距、实际头像和图标区域，变量替换后的文字也计入。
- 区分有语义的段落、短行列表、姓名和按旧宽度形成的软换行。充分使用可用宽度，处理中文标点禁则，
  保留专名与按键名称；检查续行是否错误丢失或重复增加了缩进。
- 同时检查行宽、行数、文本框高度与分页等待。选项帮助进入消息窗口时，帮助不能卡在翻页等待而阻止
  选择后的剧情推进；核对选择回调、消息协程、关闭动画及消息可见状态的完整收尾。
- 普通对白、带头像对白、气泡、帮助、滚动文字与菜单说明按各自消费者处理，不能统一套一个字数上限。

## 脚本补丁与部署

从当前汉化副本的脚本包继续工作，保留已有字体、翻译和游戏修复。`Scripts.rvdata2` 中的脚本
条目包含身份、名称和压缩源码；先确认当前结构、解压顺序及主入口，再确定修改位置。

1. 从实际调用方确认最终方法定义、`alias` 链及后续覆盖；新增补丁须在相关依赖之后、
   主入口执行之前生效。使用不冲突的内部身份和可读的补丁名称。
2. 离线读取不执行游戏主入口。脚本修改后检查语法，比较非目标条目；字面量翻译另外核对非正文 token。
3. 写回并重新读取 Marshal，核对目标内容、事件控制流程与未修改对象；字体及必要补丁一同纳入最终副本。
4. 更新地图数据后，核对 `DataManager.reload_map_if_updated` 等实际读档逻辑。
   若存档保留旧地图且当前实现依赖数据版本触发刷新，按该契约处理；不要常规重写用户存档。
5. 在任务目录保留仍有用途的基线、部署清单与恢复方法。来源漂移、条目定位不唯一或回写不一致时，
   停止受影响文件的部署并先恢复可确认的状态。

## 验证与交付

静态验证覆盖实际写回内容、编码、字体覆盖、控制码、行宽、行高、脚本顺序和 Marshal 往返。
姓名检查沿真实显示路径核对原文、当前译文和最终正文，检查重复标签与误加的外层引号，
同时保留对白中的正常人名称呼；只检查姓名框非空或控制符完整不能验收这项结果。
需要验证消息流程时，离线宿主使用实际消息、选项和解释器实现，只替换图形、音频、输入等环境边界；
围绕已确认的风险检查翻页、选择确认／取消、取消后重开、隐藏恢复和资源释放。

单独报告静态检查、离线流程、原生启动和内容实机验收。离线绘图或预览标明来源，
不记作原生 RGSS 渲染通过；宿主 Ruby 的行为也不自动代表游戏运行库的行为。

启动、截图、键鼠与游戏内操作遵守当前用户和工作区的授权，本技能不新增 Computer Use 授权。
已有启动检查授权按其范围执行，其余交由用户验收或按具体问题处理。交付清单包含标题、菜单、
姓名、头像、旁白、长对白、选项帮助与旧存档，并说明实际检查到的范围。
