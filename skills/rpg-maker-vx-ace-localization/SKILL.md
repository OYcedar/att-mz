# VX Ace／RGSS3 游戏汉化

沿用 [ATT 翻译主线](../translate-with-att/SKILL.md)，通过 Generic JSONL 处理 RPG Maker VX Ace（RGSS3，基于 Ruby 1.9.2）的提取、写回与显示适配。所有操作在隔离副本中进行，原版保留为只读基线。

默认保留现有视觉设计（修复缺字、乱码、断行、溢出和帮助容量属于正常汉化）。**仅当用户明确要求美化或重做界面时**，才读取并执行 [消息界面现代化](references/message-ui-modernization.md)。

## 1. 确认引擎与读取方

核对 `Game.ini`、`.rvdata2` 数据、`Scripts.rvdata2` 及 `.rgss3a` 归档的实际加载关系。离线转换可使用新版 Ruby，但注入游戏的脚本必须兼容 RGSS3（Ruby 1.9.2）的语法与 API。

## 2. 建立可逆的文本映射

生成输入前读取 [Generic JSONL 规格](../../docs/generic/jsonl.md)。先用包含数据库字段、对白、选项和脚本的代表性材料验证 Marshal 无损往返，确保 `Table`、`Color`、`Tone` 及自定义序列化对象完整保留。

按显示消费者确定提取范围：

| 来源 | 提取与写回判断 |
| --- | --- |
| 数据库字段 | 区分名称、说明、备注中的显示正文与标签、资源键、公式、ID |
| 事件消息 | 追踪 `101/401` 消息头及正文，保留头像、背景、位置、缩进和事件顺序 |
| 选项与帮助 | `102` 选项及其帮助消费者共同检查；`108/408` 注释仅在被插件用于显示时提取 |
| 滚动文字 | `105/405` 的显示尺寸、字号和滚动行为单独核对 |
| Ruby 脚本 | 追踪 `draw_text`、`draw_text_ex`、词汇表和插件界面；按字面量边界处理引号、转义、插值和 heredoc |

- 按 [Generic 分组规则](../../docs/generic/jsonl.md#3-从源格式建立-group-与文件范围)沿事件执行顺序将连续消息块、旁白和选项归入同一语境 Group（翻页不作为切断语境的边界），每个写回位置保留为独立 Unit。
- 原文将说话人姓名放在消息首行或前缀时，在映射中明确姓名与对白边界；能拆分的拆为同 Group 内的独立 Unit，译后统一姓名译法，避免重复追加姓名标签。
- 事件正文行数变化时按原块重建 `101/401` 指令序列，保持后续事件指令与分支结构不漂移。

## 3. 字体、编码与排版

- **字体注册**：私有字体需在创建 `Font` 对象前可用；`Font.exist?` 检查的是字体 family 名称而非文件名。Windows 路径注意 RGSS 字节编码转换，优先使用 ASCII 相对路径注册，并保留回退字体或符号字体。
- **文件编码**：Marshal 字符串、Ruby 源码和 `Game.ini` 分别按实际读取方要求的编码保存（如 `Game.ini` 的 ANSI/系统代码页）。
- **宽度与折行**：依据 `Bitmap#text_size` 或校准后的字体度量计算实际像素行宽，扣除边距、头像与图标占位。引号对白按[主技能的续行标准](../translate-with-att/SKILL.md#6-writeback)在最终换行处重建全角缩进（预算行宽时先扣除缩进宽度），跨页或硬换行时保持引号闭合状态跟踪。
- **窗口与事件等待**：同时检查行宽、行数与文本框高度。选项帮助进入消息窗口时，确保选择确认或取消后正确清理暂停与协程状态，避免卡在翻页等待。

## 4. 脚本补丁、验证与交付

1. `Scripts.rvdata2` 新增补丁放在相关依赖之后、`Main` 执行之前，使用不冲突的条目 ID 与清晰名称。
2. 地图数据更新后，检查 `DataManager.reload_map_if_updated` 等旧存档读档刷新逻辑。
3. 核对 Marshal 往返、脚本语法、编码、字体覆盖、控制码与排版行宽。完成后交付汉化副本，并列出需人工实机确认的场景（头像对白、旁白、长对白分页、选项帮助与旧存档读取）。
