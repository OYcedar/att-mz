MV / MZ 四条纵向切片

两个 CLI 命令域复用 src/rpg_maker 中同一套项目、提取、翻译与写回能力。MZ/MV 的差异只停留在游戏目录布局，以及 MV 第一条 401 的姓名投影。

图中只画当前职责 人写外部定义统一为 TOML；共享能力不建立未知引擎 trait 或平行的 MV/MZ 业务实现。

统一路由与共享语义

依赖从产品命令直接进入语义所有者

ProductCommand::{Mz, Mv} 各自拥有 CLI 契约与 RpgMakerLayout
→
ProductionRpgMakerCommandRunner 持有项目租约，解析并最终保存运行方案，把 Init / Extract / Translate / WriteBack 路由到唯一共享能力网络
MZ 布局适配 GAME_ROOT/data · GAME_ROOT/js/rmmz_core.js projects.root/mz/name
MV 布局适配 GAME_ROOT/www/data · GAME_ROOT/www/js/rpg_core.js projects.root/mv/name
01 Init收敛项目、冻结来源与当前 schema
  1. 布局边界验证游戏根

    MZ 确认 data/js 与 rmmz_core.js；MV 确认 www/data、www/js 与 rpg_core.js，不探测或自动修正。

    src/rpg_maker/init.rs · src/rpg_maker/mod.rs
  2. 项目租约与来源指纹

    项目、锁和发布锁按 engine 分开；冻结树的完整 SHA-256 是后续三命令的 freshness 权威。

    src/rpg_maker/project_lease.rs · src/rpg_maker/project.rs
  3. 建立当前数据库

    核心资产结构是 standard_text_group、standard_text_unit、standard_mutation_claim；group/unit 保存 owner 内和组内自然顺序，unit 保存角色、完整源内容、源上下文、译文内容与 state，owner 同时保存 source 与 asset snapshot fingerprint。四个命令的成功运行方案与分阶段 Lua 程序快照也由项目数据库持久化。

    src/rpg_maker/project_database.rs · src/rpg_maker/project_database/run_plan.rs
  4. 一次候选发布

    MZ 保留 data/js，MV 保留 www/data/js。完全相同返回 Unchanged，否则只发布一个完整候选。

    src/rpg_maker/init.rs · src/runtime/filesystem.rs

项目身份：projects.root / engine / name。同名 MZ 与 MV 项目可以共存；已有项目省略来源路径时复用上次成功的 Init 方案。

02 Extract物化语义单元、物理修改声明与可逆 recipe
  1. Builtin 共享事件骨架

    Map、CommonEvents、Troops 与数据库条目共用遍历；101+401* 的正文、一个 102 的有序选项和 105+405* 的滚动块各形成一个完整语义单元。

    src/rpg_maker/extract/builtin.rs · src/rpg_maker/dialogue.rs
  2. 引擎姓名投影

    MZ 从可选 101.parameters[4] 建立 direct Speaker；MV 只在首条 401 上应用项目内已提交的 dialogue TOML，并生成 Literal/SpeakerSlot recipe。

    src/rpg_maker/dialogue.rs
  3. 统一 Rules TOML

    一个 [[rule]] 数组只支持 file、plugin 或任意 code+parameter，加窄路径、逐层 JSON decode 与可选 text 捕获。

    src/rpg_maker/extract/rules
  4. 三表原子 Store

    语义身份是 owner + group_location + unit_role；Value 保存为 JSON string，Lines 保存为 JSON array，物理 Mutation Claim 展开为 Intent/Exclusive 资源锁独立存放。MV 对话定义与 Builtin 快照原子切换。

    src/rpg_maker/extract/store/asset_store.rs · src/rpg_maker/model.rs
  5. 可信 Lua

    ctx.rpg_maker 复用 data、map、plugin、document 与 db 能力；跨命令插件协议留给 Lua。

    src/rpg_maker/lua · src/rpg_maker/lua/lua54.rs · src/rpg_maker/extract/lua.rs

Owner 顺序：Builtin → Rules → Lua。省略范围时复用上次成功的完整 owner 方案；显式选择精确替换方案，空 Rules 或 Lua 停用对应 owner。失败 owner 保留旧资产快照。

03 Translate按语义单元、上下文与 state 翻译
  1. 共享 Profile 与 Prompt

    [prompts] 显式提供 root、locale 与 thinking_output；Prompt 从 prompts.root/rpg_maker/locale/system.md 渲染，开启时再追加同目录 thinking.md。Planner 与 Executor 共享响应信封模式。

    src/application/config.rs · src/rpg_maker/translate/profile.rs
  2. TOML 资源边界

    Terminology 与 Placeholder 从严格 TOML 建立受信类型，再以 canonical JSON 持久化。

    src/rpg_maker/translate/planning_resource.rs · src/rpg_maker/translate/placeholder.rs
  3. 语义资产读取与 Planner

    Speaker、完整 Body、Choices、ScrollingText 与 Scalar 可以进入同一任务；相关组不拆分。Body 按完整行序列和源 Speaker 去重，Choices 保持组内独立。

    src/rpg_maker/translate/asset_reader.rs · src/rpg_maker/translate/planner.rs
  4. 最小模型协议

    user message 只用 Markdown 表达命中术语、无编号直接语境和活动 ID，例如 Body [2] (free line breaking):
    > 第一行
    > 第二行    ；JsonOnly 直接返回 ID 到字符串数组的 JSON 对象，ThinkingThenJson 先返回唯一非空 <why>...</why> 再返回同一 JSON。Reflow 允许重断行，Aligned(N) 必须逐槽对应。

    src/rpg_maker/translate/planner.rs · src/rpg_maker/translate/executor.rs
  5. 按语义单元提交

    写入前再次核对 metadata、owner 双指纹、资源快照、unit role、完整源内容与上下文，随后原子更新 standard_text_unit 并传播完整译文。

    src/rpg_maker/translate/result_store.rs

任务位置与计数：{group_location, unit_role}；confirmed/accepted/unresolved 的计数均表示语义单元，不表示模型行或物理命令。省略 Profile 时只复用上次成功的 Translate 方案，不自行选择其他 Profile。

04 WriteBack统一 Mutation、候选验证与单次发布
  1. 读取完整物化快照

    重新计算 owner asset fingerprint，验证自然顺序、recipe、语义单元、Mutation Claim、来源块与资源锁冲突。

    src/rpg_maker/write_back/asset_reader.rs
  2. 统一对话修改

    一个 ReplaceDialogueMutation 同时处理 Speaker 与完整 Body；模型正文可以从三行变为一、二或四行，验证后一次替换完整 101+401*。

    src/rpg_maker/write_back/standard.rs · src/rpg_maker/write_back/rewriter.rs
  3. 语义断行与兜底布局

    模型行保持原样，只拆分过宽行；每条语义行使用对应源模板，新增语义行与自动续行沿用确定模板。Choices 同步更新 102/402，ScrollingText 原子更新完整 105+405*。

    src/rpg_maker/write_back/standard/layout.rs
  4. Lua 编辑同一候选

    Lua 使用逻辑 data/js 路径；MV Host 映射到 www 内。脚本没有 publish 能力。

    src/rpg_maker/write_back/lua.rs · src/rpg_maker/lua
  5. 引擎布局验证与发布

    MZ 验证顶层 data/js；MV 验证顶层 www 及其 data/js。候选验证通过后只 publish 一次；项目日志只观察发布阶段与终态，不参与发布门槛。

    src/rpg_maker/write_back/publisher.rs · src/runtime/filesystem.rs

写回权威：只消费 Extract 物化 recipe；不重读 TOML，不重新运行 PCRE2。
