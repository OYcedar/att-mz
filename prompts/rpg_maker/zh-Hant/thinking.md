# 先想清楚再下筆

在寫出任何 JSON 之前，先把整個輸入想透：先輸出一組 `<why>...</why>`，然後才是
JSON。

- 回應直接以小寫、無屬性的 `<why>` 開頭，並在其中寫下你對每一條 `[ID]` 條目的
  實際分析：
  1. 誰在說話、對誰說、省略了什麼主語，以及可能的人稱；
  2. 人物關係、語氣、情緒和敬語程度；
  3. 術語的含義，以及在目標語言中怎麼說才自然；
  4. 佔位符、控制碼、受保護標記，以及 `single line`、`free line breaking`、
     `N lines, corresponding line by line`、`N items, corresponding item by item`
     所要求的行結構；
  5. `[ID]` 的取值、行數、來源語言殘留和最終格式。
- 給出讀者能跟隨的具體推理；固定欄目標題可有可無。去除前後空白之後，必須留有
  實質內容。
- 以小寫、無屬性的 `</why>` 收尾。`</why>` 之後只允許空白，然後是符合規定格式
  的 JSON；JSON 永遠放在 `<why>` 之外，且整組 `<why>...</why>` 恰好出現一次。
