# Formic 任务设计

Formic 适合批量执行同一种需要模型判断或工具查证的独立工作：调用方负责拆分单元（`plan.jsonl`）和结果归并，每个 worker 独立处理自己的分片并发布一条可单独验收的结果。

## 1. 适用边界与分片原则

判断任务是否适合拆分为同批 worker：

| 适合交由独立 worker | 应放在作业前后的全局步骤 |
| --- | --- |
| 逐文件、逐记录抽取事实或候选 | 全局去重、统一命名、总排名与跨单元汇总 |
| 对独立对象分类、审阅、核验或补全元数据 | 依赖其他单元结果或完成顺序才能作出的判断 |
| 从当前分片对象出发按需查证支持或反证 | 让搜索命中无限扩张为新的主动处理对象 |

选择分片时满足：

- 每个单元包含作出判断所需的主要上下文，且能与其他单元独立处理、独立重试；
- 初始任务说明、分片内容、工具 schema 和输出契约能进入模型安全上下文（初始用户消息不参与历史压缩，大文件应按记录、章节或语义边界切分）。

## 2. Worker 自动获得的上下文

Formic 自动向每个 worker 提供：

- 作业内一致的系统说明与 `task.md` 原文；
- 当前单元的文件、图片或行区间内容；
- 冻结并排序后的工具名称与参数 schema（只读 `input` 检索工具及配置的 MCP 工具）；
- 结构化模式下的结果 schema 与内部提交工具 `formic_submit_result`。

`task.md` 只需说明业务目标与判断规则，无需重复描述工具参数 schema 或运行配置。

## 3. 编写 `task.md` 的核心要素

一份清晰的 `task.md` 聚焦以下要素：

1. **单元目标与输出要求**：说明当前 worker 对分片内对象要交付什么字段或段落，以及各字段的业务含义、空值/`unknown` 表示方式。
2. **主动处理范围**：明确主动发现只限于“你的分片”。若允许跨分片检索完整 `input` 或调用外部 MCP 查证，说明触发条件（仅查证与当前分片对象直接相关的事实，检索中遇到的其他对象不纳入主动处理清单）。
3. **纳入、排除与停止条件**：给出可直接执行的判断规则，以及工具查证何时停止（例如取得直接证据或完成一次针对性检索后即停止，避免无进展重复调用）。

### 示例：独立元数据补全

计划文件 `plan.jsonl`：

```jsonl
{"unit":1,"files":["item-001/source.txt","item-001/cover.png","item-001/metadata-template.txt"]}
{"unit":2,"files":["item-002/source.txt","item-002/metadata-template.txt"]}
```

任务说明 `task.md`：

```markdown
# 目标

补齐“你的分片”中 `metadata-template.txt` 的字段，提交供后续汇总程序消费的单元记录。

# 规则

- 只处理当前分片中的对象；可在完整 input 或联网工具中查证与该对象直接相关的字段，查证中出现的其他对象不纳入输出。
- 每个字段标记状态：`confirmed`（有直接证据，记录相对路径/行号或来源地址）、`conflicting`（来源矛盾，保留双方值与依据）、`unknown`（完成当前材料检查和一次针对性外部查证后仍无可靠依据）或 `not_applicable`。
- 模板中的每个字段均已确定状态与依据后立即提交。
```

若启用 `--output-schema`，将可机械校验的字段类型、枚举（如 `status`）和必填约束写入 JSON Schema，`task.md` 专注于字段语义与取证边界。
