# Generic JSONL 现行规格

输入根内每个普通 `.jsonl` 文件由零行或多行 Group 组成，每条物理行恰好是一个完整 JSON
object：

```json
{"id":"scene-1","kind":"dialogue","units":[{"id":"line-1","text":"こんにちは\n世界"}]}
```

## 1. Group

Group 只允许以下字段：

| 字段 | 要求 |
|---|---|
| `id` | 非空字符串，在整个项目中唯一 |
| `kind` | 非空字符串，由外部操作者定义 |
| `units` | 至少包含一个 Unit 的数组 |

一条物理行是一个完整的语义组，始终整体处理。JSON 中的 `\n` 解码为 `text` 里的 LF，
不会产生新的物理 JSONL 行。

## 2. Unit

Unit 只允许：

| 字段 | 要求 |
|---|---|
| `id` | 非空字符串，在所属 Group 中唯一 |
| `text` | 字符串，是唯一会被翻译的字段 |

`text` 可以为空、只含空白或含 LF；CR 和 NUL 属于无效内容。一个 Unit 的源 `text`
始终对应一个目标 `text`，模型可以自由改变其中 LF 的数量。

ID 和 kind 只拒绝空字符串。纯空白字符串按原值是合法身份，其含义由外部操作者定义。
校验按原值保存身份：区分大小写，不做 trim 或 Unicode 归一化。Group ID、Unit ID 和
kind 是身份而不是文本，不参与翻译。

## 3. 从源格式建立 Group 与文件范围

外部操作者或转换工具先确认每段文本的稳定来源、自然顺序、运行时语境和写回位置，再生成
JSONL。这里的“完整来源路径”指原格式中能够稳定定位和写回的一段完整结构范围，例如一个
对象、数组元素、事件、对话块或记录。它只用于外部转换时判断关联，不是 Generic JSONL
的字段，也不要求 Group ID 按路径书写。

先把同一完整来源路径内的文本作为关联整体分析，再沿能够独立理解、按自然顺序处理并精确
写回的真实子结构划分 Group。三层边界分别承担以下职责：

- Group 是必须共同提供给模型的最小完整语境。共同决定指代、人称、语气、关系或含义的
  文本，作为同一 Group 的有序 Unit；真正能够独立理解和写回的叶子可以单独成组。
- 一个 JSONL 文件是一个 Semantic Scope，保存同一上层来源范围内、允许共同组成
  TaskBlock 的有序 Group。各 Group 自身语境完整，但可以属于同一场景、记录序列或其他
  较大的关联范围。
- Profile 目标字符数决定 ATT 如何把完整 Group 组合成 TaskBlock；Group 的边界和完整原文
  由来源语义决定。

例如，同一数组中的补丁条目、任务记录、图鉴项或配置记录可以彼此独立。每条独立记录，
或确实需要共同理解的小记录组，分别成为 Group，再由 ATT 组合 TaskBlock。只有整个源
JSON、根对象或物理文件本身就是不可再分的完整语境时，才整体成为一个 Group。

关联范围很大时，先寻找可独立理解的子记录、子段或重复项。把数百条独立记录放进一个
Group 会强制它们进入同一个模型任务；应在外部转换时修正分组，保留真实语义边界和完整
原文。重试超长任务或翻译后临时切片不能修复这个输入问题。

较小且相关的完整 Group 保持在同一个 JSONL 文件中并保留来源自然顺序。只有上层来源
范围或输出映射确实不同，才建立不同文件；为每个细小 Group 单独建立文件，会因为
TaskBlock 不跨文件而留下内容很少的任务。无关内容也不为填充任务而合并。ATT 如何在文件
内组合 Group，见 [Generic Translate 的 TaskBlock 规则](translation.md#3-taskblock)。

Scope → Group → Unit 是 Extract 保存的稳定层次；相同输入重复 Extract 必须得到相同
结构和自然顺序。

Survey 的所有权决定与 Generic 语义组分别表达处理范围和翻译语境。一个调查关系组可以包含
应当保留的内部键和需要翻译的正文；排除内部键后，相关正文仍可组成同一个 Generic Group。
不同决定引用同一个组名时，生成器按来源自然顺序合并成员，并校验该组的来源文件与 kind
一致。独立语义组使用不同组名。填写方法见[项目调查指南](../guides/translation-project.md#2-调查可见文本)。

## 4. 严格读取

以下输入会被严格拒绝：

- 重复 JSON key、未知字段或缺少字段；
- 空白物理行（每个物理行都应是一个有效 Group）；
- 无效 UTF-8、无效 JSON，或 `text` 解码后含 CR 或 NUL；
- 重复 Group ID，或一个 Group 内重复 Unit ID；
- 空 ID、空 kind 或空 units。

空输入目录和空 JSONL 文件合法。输入文件可以使用 LF 或 CRLF。ATT 递归读取输入根内、
扩展名精确为小写 `.jsonl` 的普通文件；普通但扩展名不同的文件会被跳过。符号链接、
reparse point、硬链接和其他非普通对象会被拒绝，且不会读取其目标或进入 WriteBack 输出。

自然顺序依次为规范化相对文件路径、文件内行序和 `units` 数组顺序。文件路径只决定任务
与输出位置；Group 身份由 `id` 承担。

## 5. 设计边界

需要更多语境时，把相关文本放进同一 Group 的有序 Unit。JSONL 只接受本页定义的字段；
`translate`、`context`、`role`、metadata、格式版本和私有扩展字段均不属于当前契约。

[可执行示例](examples/sample.jsonl)把同一开场场景的对话与选项写成两个有序 Group，同时
包含不同 kind 和多行 `text`。
