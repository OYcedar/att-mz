# MZ 写回流程

本文记录当前 WriteBack 已确认的现行契约与完成边界。WriteBack 指把项目数据库中的
标准译文写入一份可供后续封包消费的 MZ `data/`、`js/` 输出，不包含封包，也不把术语
数据当作译文来源。

## 1. 项目工作区

Init 把原 MZ 游戏的完整 `data/` 和 `js/` 目录导入命名项目；后续 Standard Extract 与
WriteBack 都只认识这份冻结副本，不再访问原游戏目录。

```text
<projects_root>/<name>/
├─ project.db
├─ source/
│  ├─ data/
│  └─ js/
└─ write_back/
   ├─ data/
   └─ js/
```

`source/` 的冻结是工具内只读不变量：项目代码不得修改它，每次 Standard 写回都应从
它重新生成输出。本阶段不设置操作系统只读属性，也不保存完整性摘要。

`project.db` 的 metadata 保存项目名、源语言、目标语言，以及对话正文、滚动文本和
帮助说明三个区域的每行最大全角字符数。原游戏路径仅用于 Init 导入，不持久化。

## 2. 顶层执行顺序

```text
按名称打开项目
       ↓
Standard WriteBack
       ↓
Lua WriteBack（仅显式传入脚本时）
```

顶层只编排三个直接能力：`ExistingProjectOpener`、`StandardWriteBack` 和
`LuaWriteBack`。首个技术错误停止后续阶段；已经由依赖确认的副作用不由顶层回滚。

Standard 成功会交回同一个固定最新输出及结构化报告。若用户显式选择 Lua，Lua 接收
该输出继续处理，并完整拥有自己的文件、数据库事务和协议。Lua 失败时命令失败，错误
同时说明脚本路径和已经发布的 Standard 输出路径；顶层不回滚 Standard。

## 3. Standard 业务编排

`StandardWriteBackService` 已经实现 Standard 的业务顺序，并直接依赖四个业务能力和一
个持久事件日志根：

```text
StandardWriteBackService
├─ StandardWriteBackAssetReader
├─ MzWriteBackTextLayouter
├─ MzWriteBackDocumentRewriter
├─ StandardWriteBackPublisher
└─ PersistentEventLog<StandardWriteBackRunLog>
```

固定执行顺序是：读取五张标准资产表的一致快照，按稳定顺序选择译文并完成适用布局，
构造完整 Mutation Plan，生成候选文档，发布固定输出，最后持久记录一次完整发布事件。
前四个能力目前只有由 Standard 消费的直接契约；持久事件日志只有根接口，尚无生产适配
器。

调用方可以依赖以下行为：

- 每次从完整冻结 `source/data`、`source/js` 重建固定最新输出，不在上一次输出上增量
  修补；
- 译文来自项目数据库的标准资产记录，缺少译文的叶子继续使用冻结原文；
- 成功报告统计应用译文位置、保留原文位置、自动换行文本与新增换行、续行全角缩进，
  以及需要人工换行的文本；
- “无法安全自动布局”是正常结果：对应数据库译文原样写入、进入人工处理统计，并且不
  阻止可选 Lua；
- 输出必须完整包含 `data/` 和 `js/`，发布失败不能把半成品冒充为成功结果。

专用 `StandardWriteBackSnapshot` 按文本组及精确位置保存原文、可选数据库译文和结构化
角色，不包含术语数据。`StandardWriteBackMutationPlan` 区分普通位置替换与对话、滚动
文本正文块替换，避免把会改变 401/405 指令数量的布局结果退化成普通字符串替换。

发布成功后，Standard 只追加一条 `StandardWriteBackRunLog`，其中包含项目名、固定输出
根、汇总和全部人工布局诊断。日志失败属于技术错误：Standard 返回错误并阻止顶层继续
运行 Lua，但已经确认发布的输出不回滚；错误保留输出路径和日志根错误。人工布局诊断本
身仍是正常成功结果，不会触发该失败语义。

## 4. 已确认的布局策略

布局只作用于对话正文、滚动文本和帮助/说明框，其余游戏文本不参与自动换行。帮助说明
首批只识别 `Skills`、`Items`、`Weapons`、`Armors` 的规范 `[index].description` 位置。
三个区域分别使用 metadata 中显式建立的正整数行宽。

- 对话正文和滚动文本以完整 401/405 正文块作为布局、统计和保守回退单元；
- 正文块保留每个数据库叶子的来源边界，布局不得把字符移动到其他叶子；
- 缺译叶可以参与上下文观察，但其文本和原事件命令逐字保持不变；
- 帮助/说明框只有原文存在真实换行时才启用自动换行；
- 数据库译文已有的换行始终作为人工硬边界保留；
- 算法只在符合阅读习惯的安全断点换行，不按字符上限强切；
- 自动换行发生在续行全角空格补齐之前，换行规划需预留该缩进宽度；
- 任一语义单元无法完整、安全地满足规则时，撤销该单元的自动布局并原样写入译文。

布局的 `Manual` 是正常结果，整个正文块或单个帮助字段改用原始数据库译文继续构造
Mutation，并形成一条不包含正文内容的结构化人工诊断。具体控制符、占位符、Unicode
显示宽度、断点选择和全角缩进算法尚未实现。

## 5. 当前完成边界

当前代码可以证明 WriteBack 顶层顺序、Standard 业务编排、直接依赖接口、强类型交接、
汇总映射、整块保守回退、失败短路、发布后日志失败语义、Lua 交接和人工项正常成功语
义，也可以证明项目上下文不再依赖原游戏目录。

当前仍不能声称真实目录已经递归导入、五张标准资产表已经通过真实 SQL 读取、布局算法
已经执行、MZ JSON/401/405/`plugins.js` 已经改写、固定输出已经真实发布、事件日志已经
持久化或 Lua WriteBack 已接入真实 Host。上述依赖没有空实现或伪成功。封包、历史修订、
旧项目迁移、冻结篡改检测和行宽修改命令同样不属于本阶段。旧 metadata 不提供兼容读取
或迁移，已有旧项目必须重新执行 Init。
