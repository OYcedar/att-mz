# 译文候选验收规格

本规格是 ATT 判断一个译文候选能否进入当前项目的唯一权威。模型响应、Manual、受管 Lua、
数据库重新读取和 WriteBack 不得各自解释同一条规则。各引擎负责把自己的自然 Unit、文本形状、
Placeholder 契约和当前状态交给同一个验收入口；验收成功后，后续模块直接使用该结果。

## 1. 结果类型

候选验收只有四类结果：

- `ValidatedTranslation`：已经满足本规格全部强不变量，可以保存或物化；
- `ProvenInvariantViolation`：当前候选确定违反一条强不变量，只拒绝受影响的最小自然 Unit；
- `ReviewFinding`：存在质量或运行时风险，但不能证明候选必错；候选仍然有效；
- `OperationFailure` 或 `Cancelled`：当前操作不能安全继续，与译文质量无关。

`ReviewFinding` 不能转换成 `ProvenInvariantViolation`、Rejected、非零退出或 WriteBack 阻断。
Translate 的 `Complete` 只说明计划内 Unit 都有结构合法的当前译文；译后 QA 另行给出
`clean`、`needs_review` 或 `unverified`，使用者决定是否接受。

一条规则只有同时写明权威依据、成立条件、确定性反例、最小拒绝范围和状态影响，才能成为
强不变量。测试只证明实现遵守已经确认的规则，不能把测试自身当作领域依据。缺少任一项的
判断必须成为 Review。

## 2. 强不变量

| 规则 | 权威依据与成立条件 | 确定性反例 | 最小拒绝范围 | 状态影响 |
|---|---|---|---|---|
| 响应身份可建立 | 当前模型协议已经给每个请求 Unit 分配临时自然编号；响应项必须能唯一绑定该编号 | 未知、重复或无法解析的编号 | 无法唯一绑定的响应项；根响应无法建立时为当前 Task | 唯一绑定且内容不合法的候选进入 Rejected；无法绑定的 Unit 保持 pending |
| 候选形状 | 当前 Unit 明确要求字符串数组；`fixed` 还冻结槽数 | 标量、对象、数组中含非字符串，或 `fixed` 槽数变化 | 当前 Unit | 保存可表示的候选和原因；无法表示为字符串数组时仍保存原候选 JSON |
| 固定空槽 | ATT 的明确产品契约规定：`fixed` 源槽除 U+000C 外只含结构空白时，该槽没有可翻译正文，候选必须是精确空字符串；Extract 负责冻结这些槽位 | 源 `['接受', ' ', '取消']` 的候选为 `['接受', '文字', '取消']` | 当前 Unit | Rejected |
| 可见槽不得被翻译为空 | 非空源槽是当前明确存在的文字；翻译入口不承担删除文字的含义 | 源 `['Accept', '', 'Cancel']` 的候选为 `['', '', '取消']` | 当前 Unit | Rejected；确需删除文字只能使用使用者主动选择的原始数据库 Lua |
| 字段字符格式 | 当前 Unit 的形状明确规定允许的字符；`fixed` 用数组槽表达分行，槽内不允许 CR、LF、NUL 或 BOM；允许自由重排的正文可以按该字段契约包含 LF，但仍不允许 CR、NUL 或 BOM | `fixed` 单槽含 `\n`，或任一不允许这些字符的字段含 `\r`、U+0000 或 U+FEFF | 当前 Unit | Rejected |
| 已确认 Custom Placeholder | 当前项目 Placeholder 资源由使用者或 Agent 明确确认了自然 ID、scope、精确 pattern、wrapper 和顺序策略 | 精确协议壳缺失、重复、跨槽，或非空 `text` 子槽变成纯空白 | 当前 Unit | Rejected；普通 Custom 的协议字节身份保持精确 |
| 已确认 RPG Maker 内建控制 | 当前项目的引擎、标准物理字段和 ATT 现行内建控制规则共同确定该 Unit 的控制 token | 已确认控制 token 缺失、增加或换槽 | 当前 Unit | Rejected；插件新增或未知外形只产生 Review |
| 当前状态未变化 | 提交时的来源、上下文、Unit 形状、人工译文和事务快照必须等于规划时事实 | 规划后原文或人工译文已改变 | 当前 Unit 及必须同事务提交的传播成员 | 不覆盖新状态；记录未提交或当前操作失败 |
| 物化保持结构与原子性 | JSON、事件命令、Mutation Claim、目录发布和 SQLite 事务由各自现行规格定义 | 写回需要修改未声明字段、事务结果未知或发布恢复失败 | 当前事务或当前发布目标 | 不发布不确定结果；保留类型化恢复事实 |

U+000C 是 RPG Maker Message 的换页控制字符，不属于结构空白。只有精确 Message 消费契约
成立时，它才是强控制 token；其他位置保留正文并产生 Review，不能在 Extract 或空槽检查中
被静默丢弃。

## 3. RPG Maker 内建控制

MV/MZ 的标准控制语法和标准字段消费者是 ATT 已确认的默认领域事实。开发时用于确认这些
事实的官方 core、历史实现和真实样本只属于取证依据，不进入项目运行流程；survey、Extract
和 Translate 不为每个游戏重新扫描 core、计算函数摘要或判断活动插件是否覆写标准行为。

生产实现只根据项目引擎与 Unit 的标准物理来源应用现行内建规则。Rules 捕获标准物理字段时
继承同一事实，不能按 owner 或文件 basename 另猜一遍。插件新增语法、非标准来源和未知外形
不升级为内建规则，只产生 Review；使用者明确确认后可由精确 Custom Placeholder 保护。

具体 MV/MZ 默认语法与字段范围由
[RPG Maker 规则规格](../rpg-maker/rules.md#68-内建控制符)负责。`\N<...>`、`\N1<...>` 等
inline 姓名框不是 MV/MZ 通用内建语法；MZ 原生姓名来自事件命令 101 的 speaker 字段。

## 4. 只能产生 Review 的判断

下列事实都可能提示真实问题，但不能证明候选必错：

- `source_residual`、目标语言比例、英文单词、拒答或解释文字；
- 术语、专名、文风、语义和同一称呼是否一致；
- `finish_reason` 不是 `stop`，但已经返回的自然 ID 和内容结构完整；
- 窗口宽度、换行、压缩、截断、未知控制符和运行时字体回退；
- 插件字段是否玩家可见、多个字段是否应同步；
- 没有精确消费者证据的 `%N`、反斜杠命令、姓名框或其他疑似 Placeholder；
- 静态分析无法确认的消费者、动态代码和未访问的运行时场景。

完整响应中的合法 ID 立即保存；缺失 ID 保持未完成。非 `stop` finish reason 只追加诊断，不
丢弃同一响应中的合法结果，也不触发整 Task 重试。Review 由译后 QA 汇总并生成自然 ID
返修清单，不为这些项目自动重新请求模型。

## 5. Rejected 生命周期

唯一绑定到自然 Unit、但违反强不变量的候选按当前 schema 保存候选正文、结构化原因、来源和
验收契约。默认 Translate 跳过当前 Rejected，避免重复消耗额度；只有显式
`--retry-rejected` 才重新请求。外层响应无法建立唯一 ID 映射时没有可安全保存的候选，相应
Unit 保持 pending。

合法的自动译文、Manual apply 或受管 Lua 提交必须在同一事务中写入当前译文并清除该 Unit
的 Rejected。Placeholder 或内建控制契约改变时，数据库重新读取使用新契约验收已有
当前译文：仍合法则保留；违反强不变量则保留正文并转入 Rejected，不得删除正文或继续把它
标为 Current。

## 6. 各入口的一致性

模型响应、Manual check/apply、受管 Lua、数据库重新读取和 WriteBack 必须调用同一个引擎级
`validate_candidate`。去重键必须包含当前 Unit 的完整适用验收契约，即使源文没有命中任何
控制 token；传播到每个目标前还要以目标契约复验。否则 Plain 与 Message 的同文、或零命中
源文中由候选新增的控制符，会绕过强校验。

WriteBack 只重新确认当前快照并物化数据库中的 `ValidatedTranslation`，不执行语言判断、窗口
宽度拒绝、自动布局或语义修订。任何到 WriteBack 才首次可判断的强不变量，表示上游入口没有
使用本规格的统一验收，必须修正上游实现。
