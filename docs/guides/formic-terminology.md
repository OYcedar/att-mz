# 使用 Formic 制作游戏术语表

本指南说明何时使用发行包中的 Formic，以及 Formic、当前 Agent 和 ATT 各自负责什么。
具体的语料结构、计划校验、运行、恢复和结果验收步骤只由
[游戏术语表制作 Skill](../../skills/extract-game-terminology/SKILL.md)规定；开始任务前必须
完整读取该 Skill 及其要求的现行规则。

## 1. 适用范围

从完整游戏、剧本或大量结构化文本中制作、补全或重做术语表时，使用本流程。只审查一份
规模很小的现有术语表时，Agent 可以直接按 Skill 中的通用术语规则检查，不必建立 Formic
作业。

Formic 是完整语料分片候选抓取的主流程工具，但它不决定最终术语表：

- 当前 Agent 或外部程序整理全部玩家可见文本、记录来源，并制定 Formic 计划；
- Formic 的每个 worker 只从自己负责的分片发现候选，并可查阅共同材料或外部只读资料验证
  已发现的候选；
- 全部工作单元完成并通过范围校验后，当前 Agent 或外部处理者统一纠错、区分身份、合并
  变体、去重、选择固定写法并处理待确认项；
- 只有最终消费者是 ATT 时，才把已经确认且能由 ATT 全局作用域表达的结果转换成
  [严格术语 TOML](../translation/terminology.md)。

单个 worker 的 `include`、`exclude` 或 `needs_review` 只是分片建议。计划不完整、结果缺失、
主动发现位置越出分片或关键冲突未处理时，现有结果不能称为完整术语表。

## 2. 从完整语料开始

先确认游戏版本、补丁与 MOD、源语言、目标语言、实际运行时读取的玩家可见内容、已有官方
材料和用户指定译名。语料中的每条文本都应保留自然文件名、记录、字段或行号，以及判断身份
所需的上下文；不要把失去来源的大段拼接文本交给 Formic。

RPG Maker MV/MZ 的数据库名称、说明、系统数组、地图事件和插件参数可以进入完整语料。
按字段检查名称密集位置只用于补充候选和验证身份、定义与使用范围，不能代替完整语料的
Formic 主流程，也不能直接生成最终条目。编辑器名称、内部 ID、注释和未使用资源仍需证明
会被游戏读取或向玩家显示。

## 3. 计划、运行与统一审查

外部 Agent 根据语义边界制定计划，使全部主动发现语料恰好被一个工作单元负责。每个单元
可以读取更广的语料和权威材料来核实自己分片内的候选，但不得借验证机会从其他分片新增
候选。启动前按 Skill 校验计划；输入、计划、结果和 worker 档案必须放在发行目录之外的
独立作业目录。

Formic 完成全部单元后，先按原始完整计划校验结果与主动发现位置，再开始全局审查。全局
审查以术语身份和适用范围为依据，不按原文字符串机械合并；同形异义、短词、子串、官方
写法、表记变体和证据冲突都需要回到完整语料确认。待确认项与拒绝理由保留在工作记录中，
只有确认项进入成品。

## 4. 使用发行包中的工具

发行包固定在 `tools/formic/` 提供 Formic。它使用自己的 `config.toml`，不读取 ATT 根目录
配置，也不复用当前 Agent 会话；所需模型服务、`FORMIC_LLM_PROTOCOL` 和外部只读工具按
包内说明配置。Formic v0.1.0 固定从进程当前工作目录读取配置，因此调用方式和绝对路径要求
以 Skill 为准。运行工作单元时默认使用 64 并发；只有模型服务公布的配额、明确限速或已经
复现的服务拒绝要求更小窗口时才降低。

不要把游戏语料、作业计划、任务副本、输出或 worker 档案写入 `tools/formic/`、`skills/`
或发行包其他位置。发行资源缺失、Formic 无法启动或摘要校验失败时，按
[发行物规格](../runtime/distribution.md)处理，不从其他安装临时拼接工具。
