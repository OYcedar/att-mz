# ATT 翻译项目工作指南

这份指南帮助操作者或执行者从真实游戏内容选择 ATT 项目，并把工作推进到可验证的
输出。具体命令和格式以相应现行规格为准，按需继续阅读。

## 1. 先确认真实输入和消费者

开始前确认：

- 游戏版本、补丁与 MOD 组合；
- 运行时实际读取哪些文件，而不是只看目录名称；
- 玩家可见文本位于标准数据库、事件、插件参数、脚本还是其他文件；
- 每类文本需要哪些上下文，怎样写回，怎样证明游戏实际读取了结果；
- 源语言、目标语言、术语与不可改写内容；
- 用户允许的模型、费用、项目修改和最终交付范围。

一处报错只说明一处问题，别让它替整个项目定方案。先建立文本位置清单，再选择处理
方式。

## 2. 选择一个或多个项目

| 内容 | 使用方式 |
|---|---|
| RPG Maker MV/MZ 标准数据库、事件和 Rules 可表达的字段 | 建立对应 `mv` 或 `mz` 项目 |
| 任何已经由外部工具整理成 ATT JSONL 的文本 | 建立 `generic` 项目 |
| 同一游戏同时存在上述两类内容 | 建立两个独立项目 |

Generic 是独立的项目类型，不是 MV/MZ 项目的附属模式。两个项目可以采用不同的术语、
Placeholder 和 Profile；数据库、译文状态、日志、模型任务记录和输出都分别保存。
项目状态各自维护，一段游戏文本也只交给其中一个项目。

外部操作者负责把未覆盖内容转换成 Generic JSONL，并负责消费译后 JSONL。中间转换
使用什么游戏格式、脚本语言或工具，ATT 无需了解。

生成、重做或审查 Generic JSONL 时，先按
[Generic JSONL 分组规则](../generic/jsonl.md#3-从源格式建立-group-与文件范围)确认来源路径到
Group、Unit、JSONL 相对文件和写回位置的映射。必须共同解释的内容放在同一 Group；
各自完整但属于同一场景或记录序列的小 Group 放在同一文件，并保留来源自然顺序。先按
真实关联确定边界，再让 ATT 根据 Profile 目标字符数组合 TaskBlock，不按源文件大小、
叶子数量或目标字符数机械切分输入。

## 3. 按三个阶段执行

### 提取

Init 是建立项目所需的命令，但在工作清单中归入提取阶段。

- MV/MZ：确认引擎、游戏根、来源副本、Builtin 与 Rules 覆盖。
- Generic：确认外部 JSONL 根、稳定 Group/Unit ID 和每部分内容的项目归属。
- Generic JSONL 由本次任务生成或修改时，抽查完整来源路径、最大的 Group 和只含少量
  Group 的文件，确认必要语境没有拆散、同一场景或记录序列没有分成许多小文件，并且译后
  内容能够精确写回。
- Extract 后检查数量、自然顺序、遗漏、排除项和写回身份。

### 翻译

- 尚无经过确认的术语表时，先使用
  [通用游戏术语表制作 Skill](../../skills/extract-game-terminology/SKILL.md)从实际游戏
  内容中发现、筛选和定译；
- 术语内容确认后，按 [ATT 术语文件规格](../translation/terminology.md)转换并校验，再确定
  Profile、Placeholder 和 Prompt；
- 运行 Translate 后区分 Complete、Partial 与 Unavailable；
- 审查术语、人称、语气、控制符、未译内容和源语残留；
- 少量相同原文需要不同译文时，先保留全局去重，再用独立 Lua 精确修改相应 Unit。

修改 Generic JSONL 后重新 Extract 再继续 Translate——这一步检查省不得。

### 写回

- MV/MZ 输出是可部署的游戏内容树，不是完整游戏包；
- Generic 输出仍是 JSONL，外部操作者负责后续转换；
- 检查输出位置、完整差异、未译原文、控制符与实际运行结果；
- 目录存在或命令退出码，单独都不算发布成功证据。

## 4. 继续、返修与恢复

继续旧任务时，先读任务清单，再核对实际程序、配置、项目数据库、输入和输出。日志
与模型任务记录用于诊断；权威状态以数据库和发布终态为准。

发现新事实时返回最早失效阶段：

- 文本来源、身份、上下文、分组或写回位置改变：返回 Extract；
- 语言、术语、Placeholder、Prompt 或译文质量要求改变：返回 Translate；
- 候选位置、布局或实际加载方式改变：返回 WriteBack。

`Partial` 和 `Unavailable` 是已确认的业务结果，但通常不表示翻译完成。SQLite 或
目录发布结果无法确认时，停止重复写入，保留现场，按诊断给出的恢复位置重新观察
权威状态。

## 5. 完成条件

只有以下事实都成立，才把任务标为完成：

- 范围内文本的来源、项目归属和写回关系清楚；
- 没有未解释的遗漏、未译、拒绝或质量问题；
- 译文已由 ATT 保存，输出由当前输入重新生成；
- 输出差异符合预期，实际消费者读取了正确内容；
- 未验证内容、人工步骤和剩余风险已经明确记录。
