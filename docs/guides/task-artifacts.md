# ATT 翻译任务材料规范

本文件管理操作者自己创建的任务清单、输入副本、备份、证据和 QA 材料。ATT 的项目
数据库、日志、任务记录、候选和发布恢复文件仍由 ATT 管理，不要手工修改或移动。

## 1. 选择安全的任务根

优先使用用户明确指定且能长期保存的位置。任务根必须位于以下目录之外：

- 原游戏与实际加载目录；
- ATT 发布目录和 Skill 安装目录；
- 配置解析出的整个 `projects.root`；
- ATT 项目的 `write_back`、`logs`、`task-records` 和恢复目录；
- 最终交付目录和系统临时目录。

可以按以下方式组织，但目录名称不是产品契约：

```text
<任务根>/
  ATT-翻译任务-<项目标识>-<YYYYMMDD>[-NN].md
  artifacts/
    inputs/
    backups/
    evidence/
    qa/
    scratch/
```

只建立实际需要的子目录。不得为了找旧清单扫描整块磁盘。

## 2. 一项任务只有一份清单

- 同一目标的未完成工作继续原清单；
- 同一交付返修时保留旧记录，追加复核 TODO；
- 新游戏版本、新范围或独立输出使用新清单，并引用旧清单；
- 多份清单同时匹配时停止选择，说明身份差异；
- 任务负责人是清单唯一写入者，协作者只写被分配的材料。

## 3. 材料名称和证据

任务材料使用：

```text
<TODO-ID>-<purpose>-<YYYYMMDD-HHMMSS>[-<RunId-or-sha256-short>].<ext>
```

已经被完成 TODO 引用的文件不得覆盖、改名或删除。证据至少记录：

- 绝对路径或 ATT RunId；
- 文件 SHA-256，或数据库查询的项目身份与观察时间；
- 使用的输入、配置、Prompt 或 Lua；
- 它证明的具体事实；
- 它属于权威项目状态、ATT 诊断还是人工 QA。

文件存在、日志写有“成功”或截图存在都不能单独证明数据库提交、目录发布或游戏实际加载。

## 4. 配置和翻译资源

- 配置记录实际命令 cwd、绝对路径、SHA-256 和本次消费的解析后根，不复制凭据。
- Rules、术语和 Placeholder 保存本轮采用输入的逐字副本与 SHA-256。
- Prompt 修改可能影响多个项目，修改前检查全部使用者和授权。
- Lua 每次记录脚本绝对路径、SHA-256、参数、ATT 结果和提交后权威状态。
- Generic 还要记录外部 JSONL 根、Extract 输入指纹，以及外部转换工具的身份。

`write_back` 会被后续运行替换。需要长期保存某轮输出时，把它复制到 ATT 工作区之外，并
记录项目身份和 WriteBack RunId。

## 5. 协作和清理

委派时说明 TODO、只读或可写范围、唯一输出路径、是否允许运行 ATT 或发出模型请求、
预期证据和停止条件。不同协作者不得写同一路径。

只可清理 `scratch/` 中未被 TODO、决定或交付记录引用的内容。清理前确认解析后的绝对目标
位于当前任务根内。其他材料默认保留。
